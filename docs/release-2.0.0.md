# Bike 2.0.0 更新说明

发布版本为 `2.0.0`，包含开发计划 R01–R14 的实现及本机验收。2026-11-10 用户确认真实 AI/MCP 接入和两台物理设备验证由用户后续补测，并授权正式发布。此版本沿用 macOS arm64、ad-hoc 签名。

本版补齐 checkpoint 的累计读取限制和身份校验，超限在上传前停止并保留本机未同步内容。应用回调和打包运行时覆盖生成取消、目标切换、组合输入、两个 MCP 客户端竞争及撤权重连。发布 review 修复了冲突恢复页无效入口、附件同步初始化并发和过期上传恢复后的租约清理竞争。

## AI 与 MCP

- 应用内生成、润色和 Markdown AI 进入差异提案。接受、拒绝及按依赖组选择共用提交入口。
- 新增子树总结、保留主题身份的结构重排、去重合并、任务拆解和同文档关系建议。去重保留子树与独有字段并调整引用。
- PRD、任务和会议纪要模板默认预览后新建文档，模板定义与 MCP 共用，新文档支持撤销。
- Live MCP 通过应用授权读取最新可提交草稿。写入请求进入应用确认，已提交结果可查询并安全重试。原 File 模式继续读取，version 3 的真实写入要求使用 Live。

## 同步与恢复

- 正文、操作、outbox、审计、回执和接收游标原子保存。
- 不同主题或同主题独立字段的并发修改自动组合，同字段与结构竞争保留候选供比较。
- 操作增量使用稳定身份、服务端持久顺序、幂等回执和有界 checkpoint 追赶。缺页先停止接收，落盘后才推进游标。
- 版本历史显示本机、远端、待传及冲突记录。冲突解决形成普通操作，撤销使用补偿并保护远端后续修改。
- 附件原件自动分块续传，显示正文和附件的不同进度。哈希、长度、格式与图片尺寸校验完成后安装，取消和配额错误保留原件。

## 界面

字体层级沿用 13px 正文、12px 紧凑动作、11px 辅助文字。按钮、关闭入口、弹窗宽度和底部操作统一。七种文档导出收进“导出”菜单，紧邻 iCloud 备份左侧，三项操作固定在工具栏右侧并与上方删除按钮对齐。左侧编辑和附件工具可单独横向滚动。

保存与清除筛选位于“更多筛选”内部并随之收叠。侧栏兼容导出、Live MCP 和协议设置采用无外框的紧凑操作行。

## 升级、导出与回退

1. 正式版使用原有 `~/Library/Application Support/bike` 数据目录。预发布使用 `~/Library/Application Support/Bike-2-preview`。beta 用户需先在预发布版导出完整工作区 ZIP，再在正式版导入，导入前保留正式版原工作区的完整备份。
2. 首次启用 2.0 操作时先保存完整 ZIP，再将正文升级至 version 3。同一事务保留升级前正文。
3. 同步先升级服务器并备份 SQLite 和附件目录，再显式启用同步空间。空间升级后旧客户端的写入返回 HTTP 426。
4. 普通 JSON 和完整 ZIP 包含正文及引用，ZIP 另带附件原件。设备 actorId、outbox、令牌、私有审计和完整模型上下文不随普通副本复制。导入会创建本机身份和新的正常操作。
5. 回到 1.7.0 时先使用侧栏“导出 1.7 兼容 ZIP 副本”，在独立旧版环境中恢复。不要让旧版直接打开 version 3 数据库。原操作日志和设备身份仍保留在 2.0 数据库。
6. iCloud 自动备份仍默认关闭并保留外部变更保护。自动附件同步与完整 ZIP 备份均保留各自入口。

## 保留和支持边界

本机审计最多 200 条及 16 MiB。待传操作和未解决冲突独立保留并保护引用附件。服务端保留最近 5,000 条完整事件及长期去重回执，落后副本通过 checkpoint 恢复。远端完成附件默认保守保留，尚无自动清理功能。

首次接入无法确认共同基线时会保留分支供比较。连接无关的新同步空间会进入保护。正式签名、公证、Intel/Universal 和新平台继续独立跟踪。

macOS 安装包使用 ad-hoc 签名，尚未经过 Developer ID 签名和 Apple 公证。首次安装可能触发 Gatekeeper 提示，按系统提示在“隐私与安全性”中确认打开。此版本通过 DMG 手动升级，应用内自动替换的正式签名验收后续完成。

完整已执行证据、用户后续补测和发布状态见 [验收记录](acceptance-2.0.0.md)、[发布 review](review-2.0.0.md) 和 [制品验证](publish-verification-2.0.0.md)。
