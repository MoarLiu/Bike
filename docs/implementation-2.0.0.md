## M0 合并机制实验

在隔离临时目录安装 Yjs 13.6.33 和 Automerge 3.5.0，使用两个克隆副本修改不同主题，并同时将 a 移到 b、b 移到 a。两者均保留独立字段。Yjs 的 JSON 状态收敛，编码状态为 159 字节。Automerge 编码为 350 字节，同字段实验通过 getConflicts 取得两个候选。两个通用数据模型均需要业务层补树环校验。一次小样本运行分别约 4.4 ms 和 32.6 ms，此数据仅用于原型观察，不能当作生产性能排名。

当前路线采用共同基线字段操作和服务端顺序日志。个人多设备已有单一 Sync Server，字段比较可复用现有身份和数据，避免同时引入通用 CRDT 文档结构迁移。该路线的收敛依赖服务端分配的持久顺序和客户端连续重放。它不声明任意独立副本的操作可以无序直接应用。

共享实现位于 shared/bike-operations.mjs。标题、正文、备注、任务和扩展字段分别比较前值。节点位置使用 parentId、afterId、逻辑时钟和操作身份。新增与移动不默认重写所有后续兄弟。结构冲突、删除与编辑竞争和同字段冲突保留完整操作候选，整个多文档批次回退。

固定测试覆盖不同节点、独立字段、同字段、同位置插入、并发移动、成环、删除对编辑与新增子节点、多文档批次及远端更新后的补偿操作。20,000 主题的文字修改生成小于 700 字节的操作包。

## 本机提交与格式

正文格式增加 version 3，v1/v2 持续可读。用户启用前通过原归档功能保存完整 ZIP，原正文在同一 IndexedDB 事务中保留为升级前副本。普通 JSON/ZIP 不携带本机副本身份、令牌和私有审计。新安装或导入副本通过本机数据库生成新 actorId。

正文、操作、必要逆向变更、回执、outbox 和接收游标共用 bike-db/workspace-store 的一个事务。v3 写入失败可以保留备用编辑副本，但返回失败，不将 localStorage 描述为成功提交。网络接收使用副本 generation 与正文 CAS，防止并发写入覆盖 outbox。

相同请求身份与相同摘要返回旧回执。不同内容拒绝。正文、日志和事务提交三个故障注入点均已测试回滚。新建文档可撤销，v3 本机撤销只补偿被操作的字段。

File MCP 对 version 3 保持读取，真实写入明确拒绝。旧格式 File 参数、锁、CAS 与快照沿用。外部文件被应用显式采纳后形成新的本机操作。

`test:compatibility-runtime` 通过打包候选的侧栏导出兼容 ZIP，在实际 1.7.0 应用的新 profile 中恢复，然后再次经候选的 ZIP 备份和升级入口迁移至 v3。身份、Markdown、备注、任务、代码、表格、链接、关系、未知字段、回收站与原始附件均核对通过，升级前 v2 正文及完整 ZIP 均保留。此脚本要求同时设置 BIKE_ELECTRON_EXECUTABLE 与 BIKE_LEGACY_EXECUTABLE。

## 协议与预算

服务端协议为 2，能力为 node-operations-v2。同步空间显式启用后，旧 PUT/DELETE、旧操作追加和清单修改在事务内返回 426。服务端正文、节点位置、事件和幂等回执同属一个 SQLite 事务。

操作包上限 4 MiB、4,000 项变更，事件分页上限 100 条和约 16 MiB。单文档 checkpoint 上限 96 MiB，组合响应预算为 160 MiB，分页绑定 cursor。outbox 上限 32 MiB。最近 5,000 条事件保留完整增量，旧事件压缩后保留去重摘要与回执，过旧客户端保护 outbox 后重新取 checkpoint。5,001 条操作的实际压缩测试验证 HTTP 410、checkpoint 与旧请求去重。回执上限 100,000，达到上限进入明确保护，禁止遗忘身份后再次执行。

beta.2 对 checkpoint 的整个分页过程执行 160 MiB 累计响应预算，并在逐文档累计超过 64 MiB 时停止。结束 checkpoint、接收每页事件及投影本机待传内容后均检查工作区预算。重复身份覆盖 tombstone，位置字典按自有键保留 `__proto__` 等有效身份。回归先在旧实现上复现四个失败，再验证停止时未推进原游标或丢弃 outbox。另以 5,001 条实际服务端操作验证落后副本取得 checkpoint 后仍可提交独立的离线修改。

操作恢复审计最多 200 条和 16 MiB，先达到预算先清理。outbox 与未解决冲突另行保留。服务端未解决冲突最多 1,000 条和 32 MiB，超过预算返回诊断。

附件单块 1 MiB、并发 2、单批 512 MiB、最多 1,000 个对象。服务端默认对象配额 2 GiB、同时保留最多 32 个上传租约。未完成租约保留 7 天，完成对象默认保守保留，尚未实现远端对象自动删除。

附件故障回归在真实 HTTP 路径上让服务器写出 512 KiB 后返回 ENOSPC。错误返回时目标对象尚未安装，本机原件未变。服务实例重建后续传并下载的字节与原件一致。

## 当前接通的入口

- Live MCP 通过 stdio、本机私有 Unix socket、主进程和可信 renderer 读取已持久保存的授权内容。服务默认关闭，连接默认只读，真实写入进入应用提案队列。重载、退出和撤权作废待确认提案。
- 应用生成、润色和 Markdown AI 输出改为差异预览。五类知识操作和 PRD/任务/会议纪要模板复用同一确认入口。
- 节点增量通过 /api/v2 接口提交和接收。首次接入保留本机基线分支，不能证明相同时进入比较。正文和接收游标先持久提交，再刷新 UI。
- 版本历史增加操作来源、差异、补偿恢复入口和节点冲突处理。解决冲突绑定当前文档摘要，后续再次变化需重新比较。
- 附件二进制通过内容哈希派生路径、持久租约与临时文件续传，完成时校验长度、格式和 SHA-256，再原子安装。远端对象采用保守保留。

## 实际修复与界面

真实 Electron 联调修复了 v3 每次保存重复规范化产生伪变更、读取屏障后的重复 blur 发布、时间戳导致提案误过期、提案语义基线与跨窗口 revision CAS 混用、旧副本接收误清 outbox 等问题。Live 的 null 包及 Unicode 令牌校验会安全拒绝，相同请求身份的候选摘要由应用持久保存并自行校验。附件复用路径也校验格式和图片尺寸。

beta.2 的 Live 复核先通过实际应用回调复现了同一请求身份并发登记两个候选，以及授权在读取屏障/回执查询期间撤销后旧请求仍可排队的问题。请求现在绑定授权代次，在每个异步边界后再次核对。候选登记检查移到回执查询之后，登记前没有新的异步间隙。同一会话中的拒绝和作废状态保留候选摘要，不重新排队。客户端摘要限制为 SHA-256 字符串。六个定向用例和实际 socket 的同身份竞争/拒绝后重试覆盖这些边界。

一次旧 Electron 回归在 AI 配置弹窗仍显示时继续点击后方按钮而超时。脚本增加表单作用域、校验结束和弹窗关闭等待后在同候选重跑，原始失败日志保留为 verification/electron-runtime-before-form-wait.log。

界面依据既有 1.6.0 规范，集中使用 13/12/11px 字体层级和 6px 按钮圆角。配置、内容、差异弹窗分别为 540/720/960px，弹窗底部操作为 38px，紧凑操作为 32px。导出菜单含七项，使用 portal 避免工具栏裁剪，支持键盘、外部点击与焦点返回。导出、iCloud 备份及载入备份右侧固定并与上方删除按钮对齐，左侧工具独立滚动。筛选动作随“更多筛选”收叠，侧栏辅助入口采用无外框操作行。

## 性能记录

beta.1 阶段同一 Apple M4、Node 26.13.0 下的模块测量使用 100 文档/20,000 主题，以及单文档 20,000 主题/200 次独立编辑。1.7.0 编辑中位数为 24.081ms、p95 为 31.369ms。候选分别为 25.075ms 和 31.902ms，p95 增长约 1.7%。GC 后 heap 从 124,498,240 增至 124,668,272 字节，约 0.14%。搜索 p95 从 0.175ms 至 0.053ms。

此模块样本不含 renderer 绘制、防抖及新协议持久化。可重复测量入口为 scripts/measure-performance.mjs。

beta.1 阶段另以实际打包应用运行 scripts/measure-electron.mjs，同样使用 100 文档/20,000 主题和 200 次编辑，保留 200 步历史。1.7.0 编辑交互 p95 为 167.644ms，候选旧格式为 182.336ms（+8.76%），候选 version 3 为 167.073ms（−0.34%）。浅色搜索 p95 分别为 270.941ms、270.098ms、279.078ms，version 3 相比基线约 +3.0%。暗色搜索基本一致。GC 后 heap 分别约为 49.60、49.85 和 34.09MB。

beta.2 最终包重复同一 UI 样本，1.7.0 编辑 p95 基线为 167.644ms。候选旧格式为 184.278ms（+9.92%），version 3 为 167.511ms（−0.08%）。浅色搜索 p95 分别为 279.231ms 和 249.612ms，暗色分别为 240.173ms 和 242.767ms。GC 后 heap 分别约为 49.86MB 和 34.09MB。大文档样本在子主题折叠后编辑根主题，保留 200 步历史。

同一最终包的小型集成夹具另记录了读取屏障往返约 10.11ms、确定性 provider 返回至提案显示约 43.80ms、点击批准至查询持久回执约 456.86ms、两端离线修改经三次手动同步收敛约 498.41ms。这些数值包含 UI 自动化与协议开销，未包含真实模型等待，不能作为物理网络 SLA。

UI 测量包含 Playwright 输入、Tab 和两个动画帧，搜索包含 180ms 防抖。version 3 在隔离 profile 内从预存基线开始，避免将大规模替换导入与稳态编辑混为同一性能样本。首次尝试通过 UI 连续替换两组大型 v3 样本触及操作包预算，因此调整了夹具初始化。不同初始化路径会影响 heap，不能将约 34.09MB 宣称为普遍内存优化。此样本未观察到超过 20% 的编辑/搜索退化，新同步协议吞吐、持久回执延迟和物理设备网络性能仍需独立记录。

## 验证状态

beta.1 的完整工程检查与目标 Node 测试为 417 项通过。beta.2 新增五个同步追赶/预算用例、一个附件磁盘故障用例、八个应用工作流用例和六个 Live 边界用例，完整工程检查为 437 项通过，30 个共享返回契约通过。应用回调直接取自 App.tsx，覆盖五类 AI 与三模板的成功预览、拒绝、过期、取消、无效输出，以及生成中切换文档仍绑定原目标。任务可部分接受，其他单一原子组拒绝空选择。

开发运行时已验证双隔离进程的离线节点合并、原件传输、冲突比较及解决、远端编辑后的撤销、确定性 provider 提案和真实 MCP SDK stdio 闭环。beta.2 扩展标题、备注、Markdown 未失焦读取、组合输入期间拒读、两个 MCP 客户端先后批准时的过期处理、撤权断开及只读重连。UI 在浅色/暗色及 1366×960、1728×1117 下检查控件、菜单、筛选收叠和 16 个弹窗实例。目标 Node 及最终打包应用的本轮结果见候选制品验证。

最终打包制品证据统一维护于 publish-verification-2.0.0.md。2026-11-10 用户确认真实 AI/MCP 接入和两台物理设备验证由用户后续补测，解除本次开发交付阻断。R01–R14 实现及本机验收完成，补测结果由用户后续填写，发布工作按后续指令执行。
