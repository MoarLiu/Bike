# Bike 2.0.1 更新说明

2026-11-13 14:19（Asia/Shanghai）公开发布，包含 Electron macOS Apple Silicon、Web、Sync Server 与 Node MCP。标签为 `v2.0.1`，源码为 `7bf6985ae5dd82ae0f0c7b57b81681a1e58b8fd0`，仓库 Latest 指向本版。下载见 [GitHub Release](https://github.com/MoarLiu/Bike/releases/tag/v2.0.1)，摘要、CI 与公开下载结果见 [发布验证](publish-verification-2.0.1.md)。

## 保存、同步与恢复

- 修复 version 3 同步应用远端结果前的草稿刷新，标题、备注和 Markdown 的最新输入通过统一保存屏障提交。
- 修复删除主题留下的位置记录、移动顺序和默认字段引起的重启后伪差异。旧操作沿用原有解释，新操作使用带版本的位置算法，保留既有操作身份和幂等回执。
- 大批编辑先作为完整提交原子保存，再分片传输并校验完整摘要。同步文档顺序，减少重复 checkpoint 数据和空同步写入。
- 首次连接遇到同 ID、不同正文的文档时暂停自动同步，手动确认并下载本机备份后进入冲突比较。
- 修复历史恢复身份碰撞、失效撤销阻塞、多标签页导航和 Web 升级恢复入口。待传操作与未解决冲突独立保留。

## 编辑、导出与 MCP

- 大纲按可见区域渲染，降低大文档的页面节点数量。改善菜单边界、弹窗键盘焦点和大量主题的目标选择。
- 修复 Markdown 内联标记、列表与表格解析，补齐 PDF 中日韩、符号和单色 emoji 字体回退，过滤 SVG/XML 非法控制字符。
- Live MCP 支持断线后重新授权连接、有限并发和仅包含变化文档的大提案。拒绝、撤权和重复请求保留明确结果。
- 修复临时文件回收、损坏历史快照隔离和备份附件保留根。服务端增加默认预览的附件维护工具与保留期保护。

## 部署与升级顺序

1. 先在每个客户端保存草稿、同步可提交修改，并导出完整工作区 ZIP。关闭使用同一同步空间的全部旧客户端。
2. 停止服务端，备份配置、SQLite 数据库及附件目录。SQLite 使用一致性备份，或在停止服务后同时保留数据库及其 WAL/SHM 文件。
3. 升级 Web/Sync Server 至 2.0.1，再更新所有 Electron、MyGO 和 Web 客户端。Web 用户需要刷新页面以加载新前端。
4. 节点同步要求 `operation-ordering-v2` 能力。旧客户端会收到 HTTP 426。不要让旧服务端或旧客户端解释 2.0.1 的新操作。
5. 升级保留旧操作和回执。首次接入保护、冲突比较和丢失确认后的安全重试继续生效。回退时使用独立环境和升级前完整备份，避免直接覆盖已经产生新操作的空间。

安装器修复配置属主、路径和 systemd 转义，使用专用服务用户并在更新后重启。Cookie 认证的变更请求增加来源校验，磁盘与忙碌错误保留可诊断状态。

附件维护应先停止写入服务并备份，再运行部署包中的 `scripts/maintain-assets.mjs` 查看预览。只有明确确认的维护命令才删除超过保留期且没有保留根引用的对象。

## 安装与支持边界

Electron 使用 `Bike-2.0.1-arm64.dmg` 手动安装。ZIP、blockmap 与 `latest-mac.yml` 保留为更新分发元数据。当前 ad-hoc 构建使用手动更新入口。

安装包沿用 ad-hoc 签名，未经过 Apple Developer ID 签名和公证，首次打开可能需要在系统“隐私与安全性”中确认。Intel、Universal 及正式签名自动替换不在本次产物范围。

MyGO 使用独立 `mygo-v2.0.1` 发布渠道，见 [MyGO 更新说明](release-mygo-2.0.1.md)。两种客户端继续隔离应用身份、数据、备份和 MCP discovery。

本地完整检查通过 560 项模块测试、30 项共享返回契约、TypeScript/Vite 构建和 MCP smoke。实际应用覆盖双进程同步、附件、冲突、AI 提案和 Live MCP。旧排序升级压力样本共 5,932 个有效旧状态，新旧操作交错均通过。详细结果见 [修复与验收](remediation-2.0.1.md)。

真实输入法、其他 macOS 版本、第二台物理设备、iCloud、真实模型账号和外部 MCP 客户端继续保留人工验收边界。受控 provider 与本机隔离进程的结果不能替代这些实机检查。
