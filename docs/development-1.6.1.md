# Bike 1.6.1 优化计划：编辑安全、同步稳定与数据保真

整理日期：2026-11-09（Asia/Shanghai）；依据 2026-11-08 的审查与 1.6.0 验收记录。

状态：本地候选开发完成，模块/浏览器/打包 DMG/部署包验收已执行；待同候选远端 CI 与人工环境证据，尚未发布。代码基线为 `0c98884`；其对应的已发布版本为 `v1.6.0`，发布提交 `c97f443`。1.6.1 的实际实现、验证结果与剩余项见 [开发记录](implementation-1.6.1.md)和[候选验收记录](candidate-1.6.1.md)。以下验收标准继续有效，不把本地证据等同于全部发布门禁关闭。

## 3. 工作包与验收标准

### O01 编辑操作保持完整文档和可回退性

实施方向：

- 拖拽提交源节点、目标节点和放置位置，由文档命令针对完整树执行；聚焦视图仅提供可见范围。聚焦根的边界操作显式校验，禁止用可见子树直接替换 `document.nodes`。
- 自动展开祖先与用户主动折叠分开处理。优先用临时导航展开状态；主动折叠仍保留原有持久化和撤销语义。无变化时保持树与文档引用。
- 内容签名成为纯函数：不在比较时迁移数据、创建随机 id 或补当前时间。空文档和缺省字段重复计算必须稳定；实际内容的外部变更仍触发 stale 保护。
- 统一“最后一个主题”的删除规则与新建入口，保证删除后可继续编辑并可撤销；弹窗打开时历史快捷键不穿透，忙碌状态的命令明确禁用或提示。

主要位置：`src/App.tsx`、`src/tree.ts`、`src/editHistory.ts`、`src/documentSignature.ts`、`shared/bike-knowledge.mjs`。

验收：包含聚焦范围外主题的多根文档，完成同级/子级拖拽、撤销、重做、保存重启后，全篇主题与 id 均正确；编辑→搜索/反向链接跳转→撤销/重做不清空历史；重复定位不递增内容保存 revision；同一空文档签名稳定，实际外部内容修改仍拒绝旧撤销。

### O02 同步不自触发、不抢焦点，失败可以收敛

- 区分本机内容编辑、同步结果应用与外部存储刷新；编辑防抖和配置轮询各自调度，无内容变化不换工作区对象、不重复保存。进行中的请求合并调度，避免重叠同步。
- 结果应用保留仍存在的活动文档、主题、聚焦节点、输入焦点及草稿。确实删除当前目标时才选择回退目标；有在途编辑时安全重试。
- checkpoint 先更新可继续使用的内存进度，再尝试持久化；保存异常要报告。重启后比较远端实际内容与待确认上传内容，只有确认一致时才能恢复基线；不能仅拿到 `currentRevision` 就自动覆盖远端。
- 按规范化服务地址隔离状态，并迁移旧单键；内容指纹统一规范化规则、排除易变时间戳和键顺序，纳入算法版本。旧指纹升级必须对账，不能直接套用新算法误判删除/修改。
- 不将未在本机成功保存的下载标记为已同步；继续保留文档顺序合并、编辑优先于删除、revision CAS 与 tombstone 保护。

主要位置：`src/App.tsx`、`src/sync.ts`、`src/documentSignature.ts`、`tests/app-sync.test.mjs`、`tests/sync.test.mjs`。

验收：空闲同步成功后不在约 5 秒再次触发；60 秒配置轮询和一次编辑防抖可分别断言；零变化不重置选择/焦点。上传成功后注入存储失败，多文档进度可继续、重启能恢复共同基线；若远端又被修改，必须保留真实冲突。A→B→A 切服务器、A→B→A 改字/撤销和只有时间戳变化均无虚假冲突或重复上传。

### O03 移动、恢复和改名共用身份维护规则

- 修复 `sourceGroups` 只移动部分候选时仍携带源文档 nodeId 的情况；源/目标两侧候选组各自有效，不把受保护的失配引用误接到同名新对象。
- 回收站恢复发生文档或节点 id 碰撞时，一次生成映射并同步更新来源、内部目标、自引用和关系端点；外部 `documentId + nodeId` 成对保留。
- 改名时统一维护结构化字段、目标文档自身 Markdown 源码与入链；保留可维护的源码格式，避免简单清掉源码丢失已有格式。一次改名仍可跨文档整体撤销。
- `createLinkedDocument` 检查绑定失败并给出明确反馈，不宣称已创建稳定绑定；处理新文档已创建的中间状态。

主要位置：`shared/bike-knowledge.mjs`、`src/trash.ts`、`src/App.tsx`。

验收：同名候选组部分跨文档移动后，来源失配状态和可用链接各自正确；碰撞恢复不指向原活跃文档；Markdown→脑图改名→Markdown→导出→重新导入保持新名称、目标身份与关系，撤销可还原。

### O04 导出内容可读、可回导，损失明确

- 表格单元格使用保留空字符串的导出规则；覆盖单列、仅表头、空单元格、不齐列和转义竖线。不要复用主题标题的“未命名主题”回退。
- 区分真实协议元数据与用户正文中的类似注释；正文内容保真，真实元数据被损坏/重复时仍明确报错，不能一律忽略校验。覆盖备注、关系标签与代码示例。
- plain Markdown 的文本空白规范化、稳定 id/关系损失分别报告；带元数据 Markdown 继续完整往返原树、文本、扩展属性与内部引用。
- OPML 保留备注换行、过滤/编码 XML 非法字符；FreeMind 对不支持的内容明确提示损失。HTML 补齐已有代码块/表格的可读输出；图片继续遵守当前仅引用/占位能力。
- 修复预览的 BOM、转义竖线来源偏移、表格吞后续段落和常见转义/标题解析问题；标签扫描跳过 wiki link 区间；文件名截断按 Unicode 字符边界处理。

主要位置：`shared/bike-markdown.mjs`、`shared/bike-knowledge.mjs`、`src/exporters.ts`、`src/App.tsx`。

验收：真实导出文件重新导入，不出现空格变占位、旧名恢复、伪元数据导致无法导入或 XML 解析失败；任何格式不能承载的内容都有准确提示。链接点击同时验证目标身份和 UTF-16 来源范围，覆盖中文、Emoji、BOM、`\|` 和 `[[文档 #主题]]`。

### O05 保存、恢复与备份有凭据、有反馈

- IndexedDB 读取失败页也能列出并下载 localStorage 备用副本；成功保存前不覆盖主库、不恢复自动备份。迁移遇到坏文档/未知版本不能静默跳过后保存成缺文档工作区，应保留原文件并说明问题。
- 工作区替换与“替换前下载副本”先刷新草稿；发生第二次保存冲突明确提示，继续执行 CAS，避免新增绕过并发保护的强制写入口。
- `acceptBackupBaseline` 纳入 ticket/已保存来源凭据与窗口归属校验。异常大 revision 不得取消有效待写任务、抬高正常来源门槛。
- 磁盘错误、权限错误和暂停有去重提示与可查看状态；预期的旧任务淘汰不刷屏。关闭刷新超时必须可见并保留后续补写凭据；不把本地保存成功描述为 iCloud 上传成功。

主要位置：`src/storage.ts`、`src/migrations.ts`、`src/App.tsx`、`electron/main.cjs`、`electron/backup-service.cjs`；窗口生命周期回归位于 `electron/window-lifecycle.test.mjs`。

验收：读取失败仍可取得完整备用文件；导入前最后一笔草稿进入保留副本。旧窗口或超大 revision 的基线请求被拒绝后，正常备份仍可继续；权限/空间不足与关闭超时可诊断；保留 1.6.0 A→B→A、外部变化暂停、载入后确认基线、重开/退出前刷新回归。

### O06 大文档有资源预算，异常结构有安全边界

- 撤销历史同时按条数和估计保留字节限界；建议以 64 MiB 作为初始测量预算，M0 后冻结口径。按唯一保留文档/结构计量，淘汰最旧记录；单条超预算的行为须明确，不允许静默失去最近操作的恢复能力。
- 优先消除改名、删除、插入父主题等路径对无关文档/整树的复制；采用路径复制或复用不可变结构。签名按不可变对象缓存并在同次提交复用，避免重复迁移与序列化。
- 恢复副本按 key/变化事件缓存，界面打开时按需解析；保存、备份复用已计算摘要，保留读取失败时的恢复入口。
- 脑图布局改显式栈与循环求极值；树遍历、迁移和快照在进入递归或序列化前检查预算。超深/超宽数据受控提示并保留原数据，禁止通过迁移 catch 静默丢文档。
- 预览解析与光标行表按源码版本缓存，编辑输入和预览更新解耦；大纲稳定回调，脑图 pan/zoom 隔离节点内容；搜索按文档预索引筛选，后续页复用查询结果，避免每页从头重扫。
- 清理删除节点后的 `labelBaselineRef`，为缓存设置生命周期。持久版本历史的全局预算另列后续设计，保留当前每文档 50 条/60 天/20 MB 策略。

主要位置：`src/editHistory.ts`、`src/documentSignature.ts`、`src/tree.ts`、`src/storage.ts`、`src/versionHistory.ts`、`src/App.tsx`、共享知识/Markdown 模块。

验收样本与测量见第 5 节。200 次独立编辑不能随次数线性保留 200 份全量大文档；缓存不能使内容修改后索引/签名陈旧；异常深宽输入不白屏、不写出部分工作区。

### O07 AI 与同步请求在整个生命周期受控

- Web 与 Electron 的计时器覆盖连接、响应头、响应体读取和解析；AI 沿用 90 秒、同步沿用 60 秒作为起点，在请求最终结束时清理。支持用户取消 AI 请求。
- 按流累计响应字节，超过预算停止读取并提示；不依赖 `Content-Length`。同步响应预算与允许文档体积协调，避免合法大文档被客户端误拒绝。
- `firstBalancedJsonSlice` 改为有界单遍扫描，兼顾字符串/转义，约束输入长度、节点数与生成深度；生成和润色统一清洗及 Unicode 安全截断。
- 超时/取消后解除 busy，迟到结果不得覆盖较新的编辑；AI 配置写入异常明确反馈。

主要位置：`src/ai.ts`、`src/sync.ts`、`electron/main.cjs`、`src/App.tsx`。

验收：永不回头、回头后 body 永不结束、持续超量 body、大量不闭合括号、取消后迟到响应，均能结束任务且保持编辑器可操作；退出后不残留在途状态。

### O08 桌面与 MCP 边界收紧

- 增加生产单实例锁，第二次启动聚焦现有窗口；保留真实 Chromium 双窗口 CAS 测试，以覆盖 Web/存储并发。
- IPC 统一校验当前主窗口、主 frame 与受信来源；网络代理目标与用户已配置地址一致。更新页限定为项目 GitHub HTTPS 地址。
- 在正式 `file://` 包内验证 CSP 实际拦截；确认缺口后补适合生产/开发环境的策略。移除正式菜单中的 DevTools/reload 快捷入口，保留开发环境调试。
- Electron/MCP 原子写入保留目标的私有权限，新文件默认 0600；符号链接要么明确拒绝写入，要么解析同一真实目标并共享锁，禁止静默替换链接。长任务锁不能仅因 mtime 超时抢占活跃写者。
- MCP JSON/导出和嵌套输入统一节点数、深度与字节预算；大输出支持显式截断/错误，不能默默把完整导出截成不完整文件。错误默认脱敏，debug 才输出本机路径。
- MCP `.backups` 增加数量与字节保留预算，写入成功后清理且保留最近可恢复副本。补符号链接启动识别；生产 asar 排除测试文件。

主要位置：`electron/main.cjs`、`electron/preload.cjs`、`electron/update-checker.cjs`、`electron/workspace-lock.cjs`、`mcp/bike-core.mjs`、`mcp/bike-server.mjs`、`package.json`。

验收：实际双开只保留一个主实例；非主 frame 的 IPC 请求被拒绝；正式包 CSP 拦截证据、正常自定义端点请求和更新跳转均通过。0600 文件写后仍为 0600；链接路径不会分叉；MCP 输出预算与输入嵌套预算覆盖所有格式，写入门禁、dryRun 和 expectedRevision 继续有效。

### O09 服务端和部署维护

- 请求超限返回结构化 413，兼顾 Content-Length 与分块请求；拒绝后有界处理/关闭连接，不能为排空无限 body 无限制消耗资源，也不能先 destroy 导致响应无法送达。客户端显示体积限制并停止无效重试。
- 严格校验布尔与数值配置；代理链不足时回退 socket 地址，部署限制后端直连。用户名错误同样完成等价密码校验；HTTPS 配置正确传递 Secure cookie，保留本机 HTTP 开发能力。
- 同步配置/DB/WAL/SHM 权限与目录权限收紧，systemd 使用私有 umask；非 systemd 启动路径降权。卸载先规范化并拒绝根目录、用户主目录等危险路径；密码文档改为 stdin/TTY。
- SQLite 增加有界 busy 等待，持续锁定返回可重试错误；用两个真实连接验证 CAS，不以绕过 revision 校验解决锁竞争。
- operations 查询增加分页、游标和单次响应预算，兼容旧调用并明确截断/后续游标。tombstone/日志物理清理延期到保留协议设计，记录当前磁盘增长边界。

主要位置：`server/sync-api.mjs`、`server/sync-store.mjs`、`server/auth-server.mjs`、`server/request-guards.mjs`、`scripts/`、配置示例与部署文档。

验收：真实 HTTP 超限请求收到 413；短代理链与字符串 `"false"` 不启用信任；两连接争写有界等待且不丢更新；新装及升级后敏感文件权限正确；危险安装目录不可删除；大量 operations 每次查询有界。

### O10 让回归覆盖实际发生问题的路径

- 先保存失败场景，再修 owning source。修 stale-lock 测试的 100 ms 负载敏感预算或注入可控时序；测试应用级等待预算与生产锁超时分开，不修改生产互斥规则来迁就测试。
- 保留模块/回调测试，新增真实 React/Electron/HTTP 集成，覆盖聚焦拖拽→保存重开、导航→撤销、自动同步调度→结果应用、AI body 挂起和备份基线。`applySyncedWorkspace` 不再在对应高风险测试中整体打桩。
- fake 的异常数组在清理阶段统一断言为空；用隔离模块/全局恢复避免用例污染。搜索复杂度断言使用扫描计数/缓存命中，耗时记录放到固定样本性能流程。
- 补共享声明缺失字段与返回类型，建立能对照实现的类型契约检查；仅把 `.mjs` 加入 tsconfig 不等于声明与实现自动一致。优先针对公开 API 建立检查，全面共享层类型迁移另行评估。
- 固定 CI Node 22.13.0，增加 Node 22 系列另一明确版本的兼容性任务并记录 Electron 内置运行时。常规 CI 跑测试、类型/契约、构建、MCP smoke、差异检查；配置超时与并发控制，固定 Action 提交。
- 提供一个串联本地质量检查的命令，确保 MCP smoke 不被漏跑；现有 CI 已单独跑 smoke，不重复建立相同检查。制品阶段验证包内模块、版本/架构、资产清单及摘要。

验收：新增失败用例在修复前可触发、修复后通过；关键集成确实运行未跳过。相同候选提交通过 Linux/macOS CI 与第 5 节运行时门禁，证据按模块/浏览器/原生/跨设备分层记录。
