## 复现和修复

| 编号 | 级别 | 触发与影响 | 修复与验证 |
| --- | --- | --- | --- |
| R17-01 | P1 | 附件名或替代文字包含方括号时，导出的 Markdown 标签含转义字符，旧解析器错误截断标签。编辑源码后丢失附件引用，预览也无法识别图片 | 附件解析器与预览支持转义标签。回归覆盖图片、普通文件、方括号、反斜线和替代文字，安装包使用“路线截图 [1].png”经过源码编辑与四视图验证 |
| R17-02 | P1 | 本机 v2 工作区拉取纯文本 v1 远端时，被替换文档进入本机回收站，保留下来的附件仍要求 v2，合成结果却声明 v1，持久化失败 | `retainLocalTrash` 按最终文档和回收站重新确定版本。回归覆盖第一次拉取与再次拉取，保留回收站对象复用 |
| R17-03 | P2 | 附件对象摘要不符时，读取会正确拒绝，但从正确 ZIP 恢复也复用同一个拒绝路径，导致有效备份无法修复损坏对象 | 完整 ZIP 校验通过后，安装阶段允许修复明确的摘要错误。先保留损坏字节，再原子安装已校验对象。模块测试与安装包“补齐附件”入口验证正文保持及原始字节恢复 |
| R17-04 | P1 | 结构化文档首次编辑 Markdown 时，文档尚无持久源码基线。即使只修改一行主题文字，保守身份匹配也可能生成新 ID | 在 UI 解析入口使用当前展示的生成源码作为首次编辑基线。保持共享解析器对其他来源的保守匹配。回归及最终安装包验证主题 ID 和附件引用保持 |

## 发布门禁

开发计划 A10 将 Developer ID 签名、公证、stapling 和下载后首次启动验收列为 P0。

本机有效 Developer ID Application 身份数量为 0。当前环境缺少 `CSC_NAME`、`CSC_LINK` 和 `APPLE_KEYCHAIN_PROFILE`。仓库未配置签名或公证 secret，`macos-release` 环境的 secret 列表无法取得。正式签名脚本会在进入打包前报告缺少身份及公证凭据。

因此当前 alpha.2 制品使用 ad-hoc 签名，正式 1.7.0 的签名门禁保留为未完成。同一正式候选提交的远端 CI、正式签名 DMG 与带隔离属性的首次安装仍待验证。

真实 Finder 拖入、系统剪贴板、中文输入法、完整窗口/缩放/多图矩阵、两设备 iCloud，以及 Intel 实机和真实幕布样本继续沿用开发计划中的验收边界。此次粘贴和拖入检查通过 DataTransfer/File 合成事件进入正常处理器。

外部发布按 `macos-github-release` 技能第 9 节，在提交内容、正式版本与标签、最终制品摘要及发布操作明确后取得确认。
