# Bike 后续版本规划

更新日期：2026-11-08
最近已发布版本：`v1.5.0`（`88bc974`）；当前工作区准备 `1.6.0` 发布候选。

1.6.0 详细计划：[开发计划](development-1.6.0.md)，当前已完成主要实现与本机验收，进入发布准备；尚未发布。

## 0. 产品定位（2026-11-08 确认）

Bike 做本地优先的**个人知识工具**，以 **Electron macOS 桌面版为主**。这个定位带来以下取舍：

- 多设备同步保留，但只服务个人；文档级同步为主，节点级自动合并是体验优化，不是协作前置。
- Web 自托管版进入维护模式：继续修复问题和安全更新，不新增 Web 专属功能；Sync Server 保留，用于个人多设备同步。
- MCP/AI 是个人知识工具的核心差异化，优先级高于面向多人协作的能力。
- 不做：多人实时协作、团队空间、账号体系、移动端、Windows/Linux 桌面版（均不在当前路线内）。

## 1. 现状梳理

### 已具备的能力

- 同源树形数据：大纲、思维导图、演示、Markdown 四种视图。
- 编辑能力：层级调整、折叠、聚焦、拖拽排序、任务、备注、颜色、标题级别、行内格式、表格、代码块。
- 知识组织：全文搜索、`#标签`、`[[文档名]]`、最近编辑。
- 导入导出：JSON、Markdown、OPML、FreeMind、HTML、PDF。
- 数据保护：IndexedDB revision 检查、多标签页冲突处理、独立备用副本、恢复前下载备份。
- 同步：独立 SQLite Sync Server，文档级 revision、tombstone、自动同步。
- AI 与 MCP：用户自配模型的“生成/润色”；MCP 支持读取、搜索、导出和带 `dryRun`、`expectedRevision` 的受控写入。
- 发布：Electron macOS Apple Silicon DMG、Web/Sync Server 部署包和 curl 安装器。
- 编辑安全：文档内容撤销/重做、30 天回收站、本地版本历史；恢复前和同步替换前保留快照。
- 质量：1.5.0 验收记录为 197/197 测试、生产构建和 MCP smoke 通过；仓库已配置 Linux/macOS CI。

### 主要缺口与风险

| 类别 | 现状 | 影响 |
| --- | --- | --- |
| 编辑安全的后续约束 | 1.5.0 已提供撤销、回收站和历史；新建文档不在撤销栈中 | 1.6.0 链接、重命名与关系命令必须接入同一回退机制，不能弱化并发保护 |
| 代码结构 | `src/App.tsx` 仍集中大量状态、同步与视图；1.5.0 已拆出部分核心模块与组件 | 1.6.0 索引、链接、备份调度和新面板需继续拆分 |
| 附件 | 图片只有 `imageName` 占位，没有本地附件库 | 笔记、脑图和导出能力受限 |
| MCP 数据新鲜度 | 1.6.0 提供可选自动备份，MCP 仍读写备份 JSON，不自动载入外部写回 | 备份关闭或尚未完成时仍可能读到旧内容，实时桥留待后续版本 |
| 同步合并 | 同一文档两端修改时只能人工选择上传或拉取 | 多设备使用越频繁，冲突体验越差 |
| 知识连接 | 1.6.0 已实现补全、反向链接、改名跟随和同文档主题关系 | 跨文档图谱、附件及更全面的跨设备验收留待后续版本 |
| 工程交付 | 已有 GitHub Actions；DMG 未公证，仅 arm64 | 本机构建与实际制品验收仍是门禁，外部用户安装门槛仍需改善 |
| 包体积 | PDF 字体和相关依赖位于按需加载的大体积 chunk | 首屏不受影响，但导出功能更新体积偏大 |

## 2. 规划原则

1. 先保证可回退，再扩展写入能力。撤销、回收站和快照应早于附件、AI 批量改写和自动合并。
2. 每个版本只设一个主题，避免同时调整数据模型、同步协议和大段 UI。
3. 数据模型变更集中进行，优先采用可选、独立版本化字段；需要提升 Workspace 版本时另行设计迁移、回滚和导出兼容。
4. MCP、AI、同步都调用同一套文档操作层，避免三套写入逻辑。
5. 保持本地优先：无服务器时所有核心功能可用，同步和 AI 都是可选增强。

## 3. 版本路线

### 1.5.0：可靠编辑基础（已发布）

目标：让用户敢于大胆编辑和使用 AI。

- 撤销/重做：基于统一文档操作记录，支持 `Cmd+Z`、`Shift+Cmd+Z`，覆盖文本、层级、拖拽、删除、格式和 AI 写入。
- 回收站：文档软删除，支持恢复、彻底删除和自动清理期限。
- 本地版本历史：按时间和关键操作生成文档快照，支持预览、对比摘要和恢复。
- 编辑提交接入统一历史模块，并拆分回收站、快照与签名逻辑；跨运行时命令仍需继续归一。
- 工程基线：增加 GitHub Actions，运行类型检查、测试和构建；撤销、回收站、快照逻辑拆分为可测试模块。

交付：文档内容修改可撤销，误删文档可从回收站恢复，快照恢复前校验并发变化，Linux/macOS CI 已建立。实现及范围见 [发布说明](release-1.5.0.md)；1.6.0 继续以这套数据保护为基线。

### 1.6.0：知识连接与桌面自动备份（发布准备中，未发布）

目标：连接文档与主题，通过来源/搜索回到具体知识位置，并自动更新用户启用的桌面备份。主要实现、本机原生和布局验收已完成，源码版本已准备为 1.6.0；远端仍为 1.5.0。详细范围见 [更新说明](release-1.6.0.md) 和 [验收记录](acceptance-1.6.0.md)。

- `[[` 文档/主题补全、未创建文档提示与创建后插入链接；稳定 id 绑定，重名需显式选择。
- 文档/主题反向链接、自动显示名跟随重命名；跨文档重命名作为一次本机可撤销操作。
- 主题级搜索、全局标签、保存筛选；命中展开祖先、定位与高亮。
- 单文档脑图关系线：独立有向虚线及标签，不改变树结构，不做全库图谱或流程引擎；原 SVG 作为语义参考。
- 收藏、最近打开和保存筛选先作为本机导航偏好；文件夹建议后移到 1.6.x（暂建议 1.6.1）。
- Electron 自动 iCloud 备份由用户启用，默认关闭，写入已持久保存版本；防抖、排队、外部文件变更即暂停。改善只读 MCP 新鲜度，不自动采纳 MCP 文件写回。
- Markdown 身份维护、无损元数据导出、Sync/MCP 兼容作为前置门槛，优先验证后再开发面板。

验收：链接不因重名、改字或复制误接；搜索与来源可定位；关系与链接随 JSON、带元数据 Markdown、Sync 和 MCP 保留；自动备份不覆盖外部写入或较新已保存内容。

建议顺序：先验证身份与格式方案，再交付“链接—改名—反向定位—撤销”切片，随后完成检索/导航、关系、备份及最终验收。粗估 26–37 个有效工作日，M0 后修订，不构成开工或交付日期承诺。

### 1.7.0：附件与发布质量

目标：补齐真实内容承载和对外分发能力。

- 本地附件库：图片和文件按内容哈希存储，节点保存附件引用；支持粘贴、拖入、预览和清理未引用文件。
- 工作区 ZIP 导入导出，包含 JSON 与附件；Markdown/HTML/PDF 导出携带图片。
- 脑图导出 PNG/SVG，演示模式支持节点图片。
- 评估 XMind 导入，用幕布导出的 OPML/Markdown 建立兼容性测试样本。
- macOS Developer ID 签名、notarization、stapling；评估 Universal 或 Intel DMG。

验收：附件可离线打开、导出后可完整恢复；正式签名 DMG 首次打开无需手动绕过安全提示。

### 1.8.0：AI 与 MCP 闭环

目标：个人知识工具的差异化主线——让 agent 读到最新内容，并让每次写入可预览、可审计、可恢复。

- 实时数据桥：在 1.6.0 自动备份与外部变更保护基础上，设计内置本地 MCP 服务或等价应用桥，处理文件写回、UI 刷新、冲突和权限。
- MCP 写入审计日志、写入前快照和应用内恢复面板。
- AI 改写先显示差异，用户逐项接受或拒绝；所有接受结果进入撤销栈。
- AI 能力扩展：子树总结、结构重排、去重合并、任务拆解、生成关系线建议。
- 提供“大纲转 PRD、任务、会议纪要”等可复用模板。

验收：MCP 与 UI 之间不会互相覆盖；任意 AI/MCP 写入都能定位来源并一键恢复。

### 2.0.0：多设备自动合并

目标：个人多设备使用时，从“文档级冲突选择”升级为“节点级自动合并”。

- 引入稳定排序键和节点级操作日志，评估 Yjs、Automerge 或自研 OT/CRDT 方案。
- 不同节点的并发修改自动合并，同一字段冲突提供节点级比较。
- 附件同步、增量传输和同步历史。
- 只读 HTML 分享页保留为低成本可选项；多人实时协作不在当前路线内。

1.5.0 已建立编辑提交和回退基础；2.0 仍需把跨运行时写入统一为明确操作协议，不能把当前快照式撤销直接当成协作算法。

## 4. 建议优先级

| 优先级 | 事项 | 理由 |
| --- | --- | --- |
| 已交付基础 | 撤销/重做、回收站、版本历史、CI | 1.6.0 保持完整回归 |
| P0（1.6.0 内） | 稳定引用、Markdown 身份与格式兼容、反向链接、搜索定位 | 知识连接闭环的共同前提 |
| P1（1.6.0 内） | 单文档关系、收藏/最近打开、保存筛选 | 增强关系表达和日常导航价值 |
| P1 | 本地附件、ZIP 备份 | 补齐内容承载能力 |
| P1 | 签名公证 | 降低真实用户安装门槛 |
| P0（1.6.0 内） | 桌面端自动 iCloud 备份及外部变更保护 | 降低手动备份负担，同时防止覆盖 MCP 或其他设备的修改 |
| P2 | MCP 实时数据桥和 AI 差异预览 | 依赖操作层与快照能力；个人知识工具的差异化主线 |
| P2 | 节点级自动合并 | 只服务个人多设备场景，价值高但改动和风险最大 |

## 5. 已确认定位与规划建议

- 产品重心：个人知识工具，不走向多人协作。（2026-11-08 确认）
- 主平台：Electron macOS 桌面版为主，Web 自托管版维护模式。（2026-11-08 确认）
- 版本历史保留策略：1.5.0 已采用本机存储、每文档最多 50 个、60 天/20 MB 限制，不参与同步；调整该策略另行规划。
- 1.6.0 范围：文件夹后移；自动备份默认关闭且由用户启用；收藏/最近打开/保存筛选本机保存。当前已实现并进入发布准备，跨设备与候选选择观察仍按验收记录保留边界。
- 附件存储位置：应用数据目录、iCloud 目录或用户自定义库。
- 签名公证预算：是否开通 Apple Developer Program 并在 CI 中管理证书。
