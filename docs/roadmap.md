# Bike 后续版本规划

更新日期：2026-11-08
基线版本：`v1.4.4`（`d9a79f5`）

## 0. 产品定位（2026-11-08 确认）

Bike 做本地优先的**个人知识工具**，以 **Electron macOS 桌面版为主**。这个定位带来以下取舍：

- 多设备同步保留，但只服务个人；文档级同步为主，节点级自动合并是体验优化，不是协作前置。
- Web 自托管版进入维护模式：继续修复问题和安全更新，不新增 Web 专属功能；Sync Server 保留，用于个人多设备同步。
- MCP/AI 是个人知识工具的核心差异化，优先级高于面向多人协作的能力。
- 不做：多人实时协作、团队空间、账号体系、移动端、Windows/Linux 桌面版（均不在当前路线内）。

## 1. 现状梳理

### 已具备的能力

- 同源树形数据：大纲、思维导图、演示、Markdown 四种视图。
- 编辑能力：层级调整、折叠、聚焦、拖拽排序、任务、备注、颜色、标题级别、行内格式、表格、代码块。
- 知识组织：全文搜索、`#标签`、`[[文档名]]`、最近编辑。
- 导入导出：JSON、Markdown、OPML、FreeMind、HTML、PDF。
- 数据保护：IndexedDB revision 检查、多标签页冲突处理、独立备用副本、恢复前下载备份。
- 同步：独立 SQLite Sync Server，文档级 revision、tombstone、自动同步。
- AI 与 MCP：用户自配模型的“生成/润色”；MCP 支持读取、搜索、导出和带 `dryRun`、`expectedRevision` 的受控写入。
- 发布：Electron macOS Apple Silicon DMG、Web/Sync Server 部署包和 curl 安装器。
- 质量：`npm test` 168/168 通过，`npm run build` 通过。

### 主要缺口与风险

| 类别 | 现状 | 影响 |
| --- | --- | --- |
| 编辑安全 | 没有撤销/重做；删除文档不可撤销；没有版本历史 | 误删、拖错、AI 改写后难以回退，是编辑器最核心的缺口 |
| 代码结构 | `src/App.tsx` 约 5,358 行，状态、同步、视图和弹窗集中在一个文件 | 新功能和回归风险持续上升 |
| 附件 | 图片只有 `imageName` 占位，没有本地附件库 | 笔记、脑图和导出能力受限 |
| MCP 数据新鲜度 | MCP 读写 iCloud 备份 JSON，桌面端备份需要手动触发 | Agent 可能读到旧内容，写入后 UI 不会实时更新 |
| 同步合并 | 同一文档两端修改时只能人工选择上传或拉取 | 多设备使用越频繁，冲突体验越差 |
| 知识连接 | 没有反向链接、链接补全、重命名跟随和跨节点关系 | 难以从“大纲工具”升级为“个人知识库” |
| 工程交付 | 仓库没有 GitHub Actions；DMG 未公证；仅 arm64 | 发版依赖本机，外部用户安装门槛较高 |
| 包体积 | PDF 字体和相关依赖位于按需加载的大体积 chunk | 首屏不受影响，但导出功能更新体积偏大 |

## 2. 规划原则

1. 先保证可回退，再扩展写入能力。撤销、回收站和快照应早于附件、AI 批量改写和自动合并。
2. 每个版本只设一个主题，避免同时调整数据模型、同步协议和大段 UI。
3. 数据模型变更集中进行，并提供 v1 到 v2 的迁移、回滚测试和导出兼容。
4. MCP、AI、同步都调用同一套文档操作层，避免三套写入逻辑。
5. 保持本地优先：无服务器时所有核心功能可用，同步和 AI 都是可选增强。

## 3. 版本路线

### 1.5.0：可靠编辑基础

目标：让用户敢于大胆编辑和使用 AI。

- 撤销/重做：基于统一文档操作记录，支持 `Cmd+Z`、`Shift+Cmd+Z`，覆盖文本、层级、拖拽、删除、格式和 AI 写入。
- 回收站：文档软删除，支持恢复、彻底删除和自动清理期限。
- 本地版本历史：按时间和关键操作生成文档快照，支持预览、对比摘要和恢复。
- 操作层抽离：把节点增删改移、格式变更从 `App.tsx` 抽到可测试的 command 模块。
- 工程基线：增加 GitHub Actions，运行类型检查、测试和构建；撤销、回收站、快照逻辑拆分为可测试模块。

验收：所有修改类操作可撤销；误删文档可恢复；快照恢复前不会覆盖未保存内容；CI 在 PR 上自动通过。

### 1.6.0：知识连接

目标：让文档和节点之间形成可浏览的关系网络。

- 桌面端保存后自动写 iCloud 工作区（可关闭、防抖、失败不阻塞编辑），同步改善 MCP 数据新鲜度。
- `[[` 文档名自动补全、未创建文档提示和一键创建。
- 节点级反向链接，标题重命名时同步更新链接。
- 全局标签页和保存筛选，搜索结果直接定位、高亮节点。
- 跨节点关系线：在树结构之外记录 `from`、`to`、`label`，脑图中以虚线箭头展示，可用于流程、依赖和因果关系；`docs/login-flow-cross-relations-demo.svg` 可作为交互参考。
- 文件夹、收藏和最近打开。

验收：链接重命名不丢失；关系线可在大纲中查看和编辑，在脑图中显示，并能随 JSON、Markdown 元数据和 MCP 输出保留。

### 1.7.0：附件与发布质量

目标：补齐真实内容承载和对外分发能力。

- 本地附件库：图片和文件按内容哈希存储，节点保存附件引用；支持粘贴、拖入、预览和清理未引用文件。
- 工作区 ZIP 导入导出，包含 JSON 与附件；Markdown/HTML/PDF 导出携带图片。
- 脑图导出 PNG/SVG，演示模式支持节点图片。
- 评估 XMind 导入，用幕布导出的 OPML/Markdown 建立兼容性测试样本。
- macOS Developer ID 签名、notarization、stapling；评估 Universal 或 Intel DMG。

验收：附件可离线打开、导出后可完整恢复；正式签名 DMG 首次打开无需手动绕过安全提示。

### 1.8.0：AI 与 MCP 闭环

目标：个人知识工具的差异化主线——让 agent 读到最新内容，并让每次写入可预览、可审计、可恢复。

- 实时数据桥：Electron 自动写出工作区或内置本地 MCP 服务，并处理应用运行中的写入锁和 UI 刷新。
- MCP 写入审计日志、写入前快照和应用内恢复面板。
- AI 改写先显示差异，用户逐项接受或拒绝；所有接受结果进入撤销栈。
- AI 能力扩展：子树总结、结构重排、去重合并、任务拆解、生成关系线建议。
- 提供“大纲转 PRD、任务、会议纪要”等可复用模板。

验收：MCP 与 UI 之间不会互相覆盖；任意 AI/MCP 写入都能定位来源并一键恢复。

### 2.0.0：多设备自动合并

目标：个人多设备使用时，从“文档级冲突选择”升级为“节点级自动合并”。

- 引入稳定排序键和节点级操作日志，评估 Yjs、Automerge 或自研 OT/CRDT 方案。
- 不同节点的并发修改自动合并，同一字段冲突提供节点级比较。
- 附件同步、增量传输和同步历史。
- 只读 HTML 分享页保留为低成本可选项；多人实时协作不在当前路线内。

进入 2.0 前需要先完成 1.5.0 操作层，否则同步、撤销、AI 和 MCP 会形成多套不一致的写入路径。

## 4. 建议优先级

| 优先级 | 事项 | 理由 |
| --- | --- | --- |
| P0 | 撤销/重做、回收站、版本历史 | 直接降低数据丢失和误操作风险 |
| P0 | 统一操作层、CI | 后续 AI、MCP 和同步的共同基础 |
| P1 | 反向链接、跨节点关系、搜索定位 | 增强产品差异化和日常使用价值 |
| P1 | 本地附件、ZIP 备份 | 补齐内容承载能力 |
| P1 | 签名公证 | 降低真实用户安装门槛 |
| P1 | 桌面端自动 iCloud 备份（1.6.0） | 改善 MCP 新鲜度和数据安全，成本低于实时数据桥 |
| P2 | MCP 实时数据桥和 AI 差异预览 | 依赖操作层与快照能力；个人知识工具的差异化主线 |
| P2 | 节点级自动合并 | 只服务个人多设备场景，价值高但改动和风险最大 |

## 5. 需要确认的产品决策

- 产品重心：个人知识工具，不走向多人协作。（2026-11-08 确认）
- 主平台：Electron macOS 桌面版为主，Web 自托管版维护模式。（2026-11-08 确认）
- 版本历史保留策略：默认保留时长、容量上限，以及是否参与同步。
- 附件存储位置：应用数据目录、iCloud 目录或用户自定义库。
- 签名公证预算：是否开通 Apple Developer Program 并在 CI 中管理证书。
