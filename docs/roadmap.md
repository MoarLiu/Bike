## 0. 产品定位（2026-11-08 确认）

Bike 做本地优先的**个人知识工具**，以 **Electron macOS 桌面版为主**。这个定位带来以下取舍：

- 多设备同步保留，但只服务个人；文档级同步为主，节点级自动合并是体验优化，不是协作前置。
- Web 自托管版进入维护模式：继续修复问题和安全更新，不新增 Web 专属功能；Sync Server 保留，用于个人多设备同步。
- MCP/AI 是个人知识工具的核心差异化，优先级高于面向多人协作的能力。
- 不做：多人实时协作、团队空间、账号体系、移动端、Windows/Linux 桌面版（均不在当前路线内）。

## 1. 现状梳理

### 已具备的能力

- 同源树形数据：大纲、思维导图、演示、Markdown 四种视图。
- 编辑能力：层级调整、折叠、聚焦、拖拽排序、任务、备注、颜色、标题级别、行内格式、表格、代码块。
- 知识组织：全文搜索、`#标签`、`[[文档名]]`、最近编辑。
- 导入导出：JSON、Markdown、OPML、FreeMind、HTML、PDF；1.7.0 增加完整工作区 ZIP、Markdown/HTML 携图包和脑图 SVG/PNG。
- 本地附件：按 SHA-256 保存图片/文件，支持选择、粘贴、拖入、四视图展示、缺失补齐与受保护清理。
- 数据保护：IndexedDB revision 检查、多标签页冲突处理、独立备用副本、恢复前下载备份。
- 同步：独立 SQLite Sync Server，文档级 revision、tombstone、自动同步。
- AI 与 MCP：用户自配模型的“生成/润色”；MCP 支持读取、搜索、导出和带 `dryRun`、`expectedRevision` 的受控写入。
- 发布：Electron macOS Apple Silicon DMG、Web/Sync Server 部署包和 curl 安装器。
- 编辑安全：文档内容撤销/重做、30 天回收站、本地版本历史；恢复前和同步替换前保留快照。
- 质量：1.7.0 发布记录包含 362 项模块测试、构建、MCP smoke、远端 CI 和最终制品验证，实机边界见 [发布验证](publish-verification-1.7.0.md)。

### 主要缺口与风险

| 类别 | 现状 | 影响 |
| --- | --- | --- |
| 编辑安全的后续约束 | 已有撤销、回收站和历史；新建文档仍有撤销缺口 | 补操作来源关联，并保护同步后远端内容不被本机撤销覆盖 |
| 代码结构 | `src/App.tsx` 仍集中较多状态、同步与视图 | 按 2.0 新链路作必要拆分，避免重写成熟功能 |
| 附件同步 | 1.7.0 已有附件库和完整 ZIP；Sync 仍只交换元数据 | 2.0 增加二进制传输、续传和远端生命周期保护 |
| MCP 数据新鲜度 | MCP 仍读写备份 JSON，自动备份不等于实时桥 | 2.0 直接读取应用最新已提交内容，并在确认后写回 UI |
| 同步合并 | 仍以文档级冲突选择为主；operation log 尚不自动应用节点操作 | 2.0 统一操作模型并实现节点合并、冲突处理和增量传输 |
| 知识连接 | 已有补全、反向链接、改名跟随和同文档关系 | 新 AI/同步路径需保留身份与引用，全库图谱另行评估 |
| 工程交付 | 已有 GitHub Actions；DMG 未公证，仅 arm64 | 本机构建与实际制品验收仍是门禁，外部用户安装门槛仍需改善 |
| 包体积 | PDF 字体和相关依赖位于按需加载的大体积 chunk | 首屏不受影响，但导出功能更新体积偏大 |

## 2. 规划原则

1. 先保证可回退，再扩展写入能力。撤销、回收站和快照应早于附件、AI 批量改写和自动合并。
2. 每个版本有明确产品主题。2.0.0 的合并范围按共同模型、AI/MCP、节点同步、附件传输分阶段验收，控制数据模型、协议与 UI 的同时变更。
3. 数据模型变更集中进行，优先采用可选、独立版本化字段；需要提升 Workspace 版本时另行设计迁移、回滚和导出兼容。
4. MCP、AI、同步都调用同一套文档操作层，避免三套写入逻辑。
5. 保持本地优先：无服务器时所有核心功能可用，同步和 AI 都是可选增强。

## 3. 版本路线

### 1.5.0：可靠编辑基础（已发布）

目标：让用户敢于大胆编辑和使用 AI。

- 撤销/重做：基于统一文档操作记录，支持 `Cmd+Z`、`Shift+Cmd+Z`，覆盖文本、层级、拖拽、删除、格式和 AI 写入。
- 回收站：文档软删除，支持恢复、彻底删除和自动清理期限。
- 本地版本历史：按时间和关键操作生成文档快照，支持预览、对比摘要和恢复。
- 编辑提交接入统一历史模块，并拆分回收站、快照与签名逻辑；跨运行时命令仍需继续归一。
- 工程基线：增加 GitHub Actions，运行类型检查、测试和构建；撤销、回收站、快照逻辑拆分为可测试模块。

交付：文档内容修改可撤销，误删文档可从回收站恢复，快照恢复前校验并发变化，Linux/macOS CI 已建立。实现及范围见 [发布说明](release-1.5.0.md)；1.6.0 继续以这套数据保护为基线。

### 1.6.0：知识连接与桌面自动备份（已发布）

目标：连接文档与主题，通过来源/搜索回到具体知识位置，并自动更新用户启用的桌面备份。版本已发布为 `v1.6.0`，发布提交 `c97f443`。详细范围见 [更新说明](release-1.6.0.md)、[验收记录](acceptance-1.6.0.md) 和 [发布验证](publish-verification-1.6.0.md)。

- `[[` 文档/主题补全、未创建文档提示与创建后插入链接；稳定 id 绑定，重名需显式选择。
- 文档/主题反向链接、自动显示名跟随重命名；跨文档重命名作为一次本机可撤销操作。
- 主题级搜索、全局标签、保存筛选；命中展开祖先、定位与高亮。
- 单文档脑图关系线：独立有向虚线及标签，不改变树结构，不做全库图谱或流程引擎；原 SVG 作为语义参考。
- 收藏、最近打开和保存筛选先作为本机导航偏好；文件夹后移到后续 1.6.x，当前 1.6.1 优先收口稳定性问题。
- Electron 自动 iCloud 备份由用户启用，默认关闭，写入已持久保存版本；防抖、排队、外部文件变更即暂停。改善只读 MCP 新鲜度，不自动采纳 MCP 文件写回。
- Markdown 身份维护、无损元数据导出、Sync/MCP 兼容作为前置门槛，优先验证后再开发面板。

验收：链接不因重名、改字或复制误接；搜索与来源可定位；关系与链接随 JSON、带元数据 Markdown、Sync 和 MCP 保留；自动备份不覆盖外部写入或较新已保存内容。

建议顺序：先验证身份与格式方案，再交付“链接—改名—反向定位—撤销”切片，随后完成检索/导航、关系、备份及最终验收。粗估 26–37 个有效工作日，M0 后修订，不构成开工或交付日期承诺。

### 1.6.1：编辑安全、同步稳定与数据保真（已发布）

基于两份独立 review 与 1.6.0 验收记录，完成编辑安全、同步生命周期、身份恢复、Markdown 往返、大文档资源预算及运行时维护。工作包见 [1.6.1 优化计划](development-1.6.1.md)，结果与保留的环境边界见 [发布验证](publish-verification-1.6.1.md)。

### 1.7.0：附件与发布质量（已发布）

稳定版本为 `1.7.0`，当前完成项与环境边界见 [实施记录](implementation-1.7.0.md)。用户于 2026-11-09 确认沿用 ad-hoc 签名发布，正式签名公证顺延。

本版补齐真实内容承载和对外分发能力。详细工作包、建议数据结构、兼容与回退、资源预算和分阶段验收见 [1.7.0 开发计划](development-1.7.0.md)，以已发布的 1.6.1 为开发基线。

- 本地附件库按内容哈希存储图片和文件，建议默认使用应用数据目录。支持文件选择、粘贴、拖入、预览和安全清理，撤销、回收站与历史共同保护附件。
- 工作区 ZIP 包含 JSON 与所引用附件，支持完整性校验、空白环境恢复及缺失附件补齐。Markdown/HTML 以携图包导出，PDF 内嵌图片。
- 脑图导出 PNG/SVG，演示模式支持节点图片，统一图片加载、布局与资源预算。
- 冻结附件版本、迁移和回退方案，补齐 iCloud 完整备份、Sync/MCP 元数据保真及旧客户端写入保护。附件二进制自动同步仍按 2.0.0 排期。
- 评估 XMind 导入，用幕布导出的 OPML/Markdown 建立兼容性样本与损失矩阵，实际 XMind 导入在评估后决定。
- 本版提供 macOS arm64 ad-hoc DMG、ZIP、blockmap 与更新清单，应用内更新接入检查、下载和保存后重启安装流程。Developer ID 签名、notarization、stapling 及原生自动替换实测顺延，Universal 或 Intel DMG 继续评估。

验收要求附件可离线打开，删除后可按既有回退机制恢复，工作区 ZIP 在空白环境完整恢复，携图导出可离线阅读，最终制品通过签名校验与下载摘要验证。ad-hoc 首次安装和自动更新限制随发布说明披露。

建议先完成数据契约与存储验证，再交付“导入—撤销—重启—ZIP 恢复”切片，随后完成备份兼容、导出展示及正式分发。粗估 30–43 个有效人日，计入约 20% 集成余量后约 36–52 人日，M0 后重估。账号、外部环境与新增架构实现另计。

### 1.8.0：AI 与 MCP 闭环

**已合并至 2.0.0，不再单独开发发版。** 原实时 MCP、AI 差异确认、审计恢复、五类知识操作与模板入口全部保留在合并范围中。[原开发计划](development-1.8.0.md) 归档，后续执行以 [2.0.0 开发计划](development-2.0.0.md) 为准。

### 2.0.0：AI 知识工作流与个人多设备同步

目标：让 agent 能受控整理应用中的最新知识，让个人多台设备安全合并修改并同步完整附件。用户于 2026-11-09 确认合并原 1.8.0 与原 2.0.0 的需求，统一正式发布目标，分阶段开发与试用。

完整需求 R01–R14、工作包 W01–W11、架构验证、迁移和发布门禁见 [2.0.0 开发计划](development-2.0.0.md)。

- 共同操作基础：UI、AI、MCP 与同步共用相关文档操作规则。先验证节点身份、稳定排序、合并、持久提交和安全撤销；不把审计日志、恢复快照直接当成同步算法。
- 实时 MCP：沿用 stdio 与现有工具，新增受保护的 Live 通道，直接读最新已提交内容，确认后写回并刷新 UI。断连不自动转为文件写入。
- 差异与追溯：逐组接受/拒绝 AI/MCP 修改，在现有历史入口关联来源、原因、实际差异和恢复点。远端修改到来后，旧 AI 预览重新校验，本机撤销保护远端内容。
- AI 工作流：子树总结、结构重排、去重合并、任务拆解、关系线建议；复用已有 PRD/任务等 prompt，补应用内执行与会议纪要模板。
- 节点同步：不同节点修改自动合并，同字段及结构冲突提供节点级比较与处理；加入操作增量传输、可靠重试、checkpoint 和同步历史。
- 附件同步：复用本地哈希库与 ZIP，增加二进制自动传输、续传、完整性校验和远端生命周期保护；正文与附件进度分别显示。
- 兼容与迁移：明确服务器升级、旧端拒写、v1/v2 数据迁移与 ZIP 回退；保持 File MCP 在支持格式内的既有行为，以及备份暂停和恢复保护。

附件库、归档、通用撤销、历史面板、既有 MCP 文件锁/CAS、文档同步和旧 prompt 都是复用基础，不重复建设。文件夹、XMind、Intel/Universal、HTML 分享等另行排期，正式签名仍独立跟踪。

| 阶段 | 交付目标 |
| --- | --- |
| M0 | 先验证共同操作模型、合并机制、迁移与双客户端并发样例 |
| 2.0.0-alpha.1 | 原 1.8.0 的 AI/MCP 闭环及知识工作流可试用 |
| 2.0.0-alpha.2 | 节点合并、冲突处理、增量传输与同步历史可用 |
| 2.0.0-alpha.3 | 附件自动同步接通，完整范围进入组合验收 |
| 2.0.0-beta → 正式版 | 升级/旧端保护、两设备离线并发、恢复及最终制品验证完成 |

验收：14 项正式增量全部完成；AI/MCP 确认与同步合并边界明确，断线/重试/崩溃不重复写入或产生虚假成功；各设备结果收敛，冲突与恢复可定位，活跃附件不丢失。alpha.1 完成不代表正式 2.0.0 已完成。

旧 1.8.0 工时估算已撤回。M0 后按新增实现、必要改造、回归与集成余量重新估算，不相加旧版本数字，不预先承诺合并一定更快。

## 5. 已确认定位与规划建议

- 产品重心：个人知识工具，不走向多人协作。（2026-11-08 确认）
- 主平台：Electron macOS 桌面版为主，Web 自托管版维护模式。（2026-11-08 确认）
