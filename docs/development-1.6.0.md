# Bike 1.6.0 开发计划：知识连接与桌面自动备份

日期：2026-11-08

代码基线：`v1.5.0`，提交 `88bc97427e96b42079fb7c4ba962ba81b6e8c5cc`

产品定位：本地优先的个人知识工具，以 Electron macOS 桌面版为主。

文档状态：已按本计划实施，并完成三轮审查问题修复及本机补充验收，进入 1.6.0 发布准备，尚未发布。具体修复和验证见 `docs/review-fixes-1.6.0.md` 与 `docs/acceptance-1.6.0.md`；跨设备边界、候选选择观察和远端 CI 仍按记录保留。

## 1. 版本目标

1.5.0 已提供撤销、回收站和版本历史。1.6.0 在这个基础上解决三件日常问题：

1. 写笔记时能方便地连接其他文档或主题，改名后仍能找到它。
2. 从搜索、标签和反向链接直接回到具体主题，不再靠逐篇打开查找。
3. 桌面端在本地保存后自动更新备份，让用户和只读 MCP 更容易获得最近保存的内容。

典型闭环：在读书笔记里输入 `[[项目方案]]` → 选择目标 → 项目方案中看到来源 → 点击来源定位原主题 → 将两条主题以“依赖”关系连起来 → 修改保存后自动更新桌面备份。

不新增登录要求，不以服务器、AI 或 iCloud 可用作为核心编辑的前提。

## 2. 本次范围与取舍

| 编号 | 功能 | 优先级 | 本版边界 |
| --- | --- | --- | --- |
| F1 | 稳定文档/主题链接、`[[` 补全、未创建文档 | P0 | 正文、备注、Markdown 源码；明确目标 id；重名必须选择 |
| F2 | 文档与主题反向链接、重命名跟随 | P0 | 已解析引用；来源可定位；一次重命名可整体撤销 |
| F3 | 主题级搜索、全局标签、保存筛选 | 搜索/标签 P0，保存筛选 P1 | 本地全文匹配、片段与高亮；不做语义搜索 |
| F4 | 脑图跨节点关系线 | P1，目标纳入正式版 | 单文档、节点到节点、有向虚线和文字；不做自由画布 |
| F5 | Electron 自动 iCloud 备份 | P0 | 用户启用、写已保存版本、冲突时暂停；不自动拉取文件 |
| F6 | 收藏、最近打开 | P1，目标纳入正式版 | 本机导航偏好；保留“最近编辑”，不复用历史移动端字段 |
| F7 | 格式兼容、撤销与性能门禁 | P0 | 新数据在导出、同步、MCP 与恢复中正确保留 |

范围调整建议：

- 原路线图中的“文件夹”后移至 `1.6.x` 单独设计，暂建议 `1.6.1`。本版已经涉及引用身份、搜索索引、关系数据和备份调度，再引入工作区分类元数据同步会扩大迁移风险。
- 关系线保留在本版，但限定为单篇脑图的附加关系；跨文档连接由 F1/F2 负责。
- 保存筛选、收藏和最近打开先作为本机偏好，避免为导航引入新的同步协议。
- F4/F6 若不能通过门禁，须显式调整计划与发布说明后再决定拆版，不在发布时默默省略。

### 本版不包含

- 全库知识图谱、自由拖动关系布局、流程执行器、任务依赖调度。
- 多人协作、团队空间、新账号系统、CRDT、节点级自动同步合并。
- 附件库、图片同步、XMind 导入、正式签名公证。
- MCP 实时写回桌面 UI、文件自动双向合并、写入审计面板。
- PWA 或 Web 专属功能、移动端及其他桌面平台。

## 3. 1.5.0 代码现状及实施影响

以下结论来自当前代码核对，属于本版设计约束。

| 现状 | 主要位置 | 对 1.6.0 的影响 |
| --- | --- | --- |
| `extractLinks` 仅用正则提取括号内文字 | `src/tree.ts` | 无目标 id、重名处理和源码位置；不能直接承担稳定引用 |
| 标签列表来自当前文档，搜索只筛文档 | `src/App.tsx` | 需要工作区派生索引、主题级结果与统一定位入口 |
| “快速访问”为占位入口，“最近编辑”按 `updatedAt` 排序 | `src/App.tsx` | 可替换占位入口；“最近打开”需独立记录 |
| `isShortcut` 是已保留的兼容字段 | `src/types.ts`、迁移逻辑 | 不把它重新解释为收藏，避免改变原有含义 |
| `commitWorkspace` 记录已有文档前后变化 | `src/editHistory.ts`、`src/App.tsx` | 跨文档重命名可利用现有多文档撤销；新建文档仍不在撤销栈 |
| Markdown 以原文缓存保格式，节点按路径与文本匹配重用 id | `src/markdown.ts` | 修改标题文本可能得到新节点 id；稳定主题链接必须先补身份维护与源码映射 |
| Markdown 没有 Bike 文档级元数据协议 | `src/markdown.ts`、`src/exporters.ts` | 关系与引用不能只加类型字段，必须设计有损/无损导出和往返测试 |
| 原始 Markdown 可能绕过常规序列化直接导出 | `src/App.tsx` | UI、MCP 导出都要经过同一格式策略，避免新元数据被绕过 |
| MCP 迁移保留扩展字段，但 compact 输出只选定固定字段 | `mcp/bike-core.mjs` | “文件中保留”不等于“agent 能读到”，需扩展读取结果 |
| Sync Server 使用文档 JSON 和 revision | `src/sync.ts`、`server/sync-store.mjs` | 文档级新字段可随文档传输；工作区偏好不会自动同步 |
| iCloud 写入有文件锁、原子替换和内容哈希保护；基线哈希由前端保存 | `electron/main.cjs`、`electron/workspace-lock.cjs`、`src/backup.ts` | 自动备份必须统一队列和基线，不能简单在每次编辑后调用手动备份函数 |
| MCP 可以修改同一工作区 JSON 文件 | `mcp/bike-core.mjs` | 自动备份发现外部修改时必须暂停，防止覆盖 agent 的写入 |
| 数据加载失败、多标签页冲突会暂停保存 | `src/storage.ts`、`src/App.tsx` | 同时暂停自动备份，不能把未确认的旧状态写成最新副本 |

## 4. 用户流程与交互边界

### 4.1 写入链接

1. 在主题正文、备注或 Markdown 源码键入 `[[`，在光标附近显示候选框。
2. 默认搜索正常文档标题；输入 `文档名#` 后搜索该文档内主题，以路径区分同名主题。
3. 使用上下键选择、Enter 确认、Escape 取消；中文输入法组合输入期间不抢 Enter。
4. 选择候选后插入可读的 `[[文档名]]` 或 `[[文档名#主题名]]`，同时绑定目标 id。
5. 无结果时提供“创建文档并链接”。创建和插入在一个本机提交中完成，继承来源所用的文档创建规则。

同名文档或主题必须明确选择，不根据列表顺序猜测。新建后不强制跳离当前文档。

1.5.0 不记录文档新建的撤销，因此“创建并链接”的一次撤销只撤销来源中的链接插入，保留已建文档；提示该行为，新文档仍可移入回收站。不要为了这个入口扩大本版到全工作区撤销。

### 4.2 打开链接与返回

- 正常点击输入框仍用于编辑；大纲/脑图编辑中用 `Cmd/Ctrl+点击` 或详情栏链接按钮跳转。
- Markdown 预览直接点击内部链接跳转；不把内部链接交给外部浏览器。
- 统一定位过程：提交当前草稿 → 确认目标仍存在 → 打开目标文档 → 展开祖先 → 必要时退出局部聚焦 → 选中并滚动到目标 → 短暂高亮。
- 工具栏提供后退/前进，最多保留 50 个本机跳转记录。先不新增会与脑图现有快捷键冲突的组合键。
- 点击搜索、标签命中、反向链接和关系目标，均走同一定位服务。

### 4.3 反向链接

- 当前文档显示“引用此文档”的来源；选中主题时可切到“引用此主题”。
- 每条显示来源文档、主题路径、命中片段及正文/备注标记。
- 同一来源主题多次引用同一目标时合并显示并计数，默认排除回收站。
- 无解析结果与目标失效分开显示，不能把“未找到”误报为“没有引用”。

### 4.4 搜索、标签与快速访问

- 搜索结果按文档分组，默认最多显示 100 条主题命中，提供“加载更多”。
- 显示标题、主题路径、正文/备注片段及匹配高亮；标题命中定位到文档头部。
- 全局标签页显示所有正常文档中的标签和命中数，点击后进入同一结果列表。
- “快速访问”包含收藏、最近打开和已保存筛选；“最近编辑”继续按内容更新时间显示。
- 本版筛选条件为关键词、标签、文档范围、任务状态与是否收藏；不提供复杂查询语言。

## 5. 数据设计与身份规则

### 5.1 文档级新增字段

建议沿用 `Workspace.version = 1`，在文档增加可选、独立版本化的知识连接字段。以下是设计草案，不是本次提交的运行时代码。

```ts
interface DocumentKnowledge {
  version: 1;
  references: DocumentReference[];
  relations: NodeRelation[];
}

type ReferenceSource =
  | {
      kind: "node-field";
      nodeId: string;
      field: "text" | "note";
      start: number;
      end: number;
      raw: string;
    }
  | {
      kind: "markdown";
      start: number;
      end: number;
      raw: string;
      sourceNodeId?: string;
    };

interface DocumentReference {
  id: string;
  source: ReferenceSource;
  target: { documentId: string; nodeId?: string };
  labelMode: "auto" | "custom";
}

interface NodeRelation {
  id: string;
  fromNodeId: string;
  toNodeId: string;
  label: string;
}

// OutlineDocument 新增 knowledge?: DocumentKnowledge
```

约定：

- 字符位置使用 JavaScript UTF-16、`[start, end)`，每次读取/修改必须校验 `raw` 与当前内容一致。
- 目标始终按 id 解析；显示名来自目标或显式自定义文案，名称相同不代表相同身份。
- `missing`、`ambiguous`、`sourceMismatch`、`deleted` 等状态由当前工作区派生，不作为永久事实写入。
- 回收站、快照保留连接原始数据，但不进入正常知识索引。对象恢复后重新解析状态。
- 反向链接、标签与搜索结果是可重建索引，不重复塞进工作区或同步文档。
- `knowledge.version` 大于本客户端支持范围时原样保留，禁止修改该部分并提示升级；不得在迁移时清空。

### 5.2 链接解析策略

| 输入或状态 | 行为 |
| --- | --- |
| 补全框选中目标 | 保存明确 id 绑定，今后不因重名自动改变目标 |
| 原有 `[[文档名]]`，恰好一个同名文档 | 可按名称解析为旧式弱链接，显示可跳转；不因打开文档就批量改写数据 |
| 原有 `[[文档名#主题名]]` | 按唯一文档、唯一主题解析；重复主题必须让用户选择 |
| 同名候选多个 | 显示待选择，不生成错误反向链接 |
| 绑定目标移入回收站/删除 | 提示“目标已删除”，可进入回收站或显式重新连接；不绑定到后来新建的同名对象 |
| `raw` 不再匹配源文字 | 标记需重新解析，不使用过期位置跳转或重命名 |
| 源链接完整删除 | 同一操作删除对应绑定，撤销时一并恢复 |
| 代码块、行内代码或转义的 `\[[` | 作为普通文本，不参与链接补全与反向链接 |

包含 `#`、`|`、`]` 或反斜杠的名称需要统一转义与解析；`|` 用于可选显示别名。解析器先处理转义与语法，再查目标，不能直接拆字符串。普通 URL 与内部链接分别处理，沿用现有安全 URL 规则。

### 5.3 重命名规则

文档标题目前按每次输入提交。本版需要引入标题草稿，在 Enter、失焦、显式保存或导航前统一提交一次“重命名”，避免每个字符都扫描整库。

重命名事务：

1. 提交相关未保存草稿，记录当前工作区基线。
2. 找到目标文档/主题的已绑定引用，以及旧名称唯一可解析的弱链接。
3. 更新自动显示名；自定义别名保持原样，但仍指向原 id。
4. 同时更新对应正文、备注、Markdown 原文和绑定位置；不在代码块或普通文本中做全局字符串替换。
5. 一次 `commitWorkspace` 更新所有受影响文档，逐篇标记修改；“撤销重命名”整体回退本机修改。
6. 如计算期间有新编辑、同步、导入或跨页变化，取消旧结果并重新计算。

旧名称有歧义时只更新已绑定引用，列出待处理弱链接。Sync Server 仍按文档逐篇提交，不能宣称跨文档远端原子性；同步中断时先保留 id 导航与本机提交结果，后续正常重试。

### 5.4 节点身份、复制与移动

- 同一文档内移动、缩进、改字保留节点 id，文本变化不能使稳定引用失效。
- 跨文档剪切保留节点 id，并在同一本机事务中更新相关引用的目标文档 id；切走后不得继续留有无提示的错误目标。
- 跨文档剪切时，两端都随子树移动的关系迁入目标文档；只移动一端的关系留为失效边并明确提示，不自动扩展成跨文档画线。
- 文档/子树复制分配新节点 id；复制范围内引用与关系通过 old→new 映射更新，指向复制范围之外的链接继续指向原对象。
- 同文档关系只复制两端均在复制范围内的边；跨边界边留在原文档并提示未随副本迁移。
- 删除节点保留指向它的失效引用与关系原始端点信息，供修复、撤销和历史恢复；不改连到其父节点或同名节点。用户显式删除关系则由撤销/历史保留其旧版本。
- 导入出现重复 id 时，必须输出完整 id 映射并修正文档内部连接。工作区外部链接不凭猜测重定向。

## 6. Markdown 与导出兼容

这是 F1/F2/F4 的前置条件，不能放到收尾再补。

### 6.1 编辑时的身份维护

- 为 Markdown 解析提供节点/正文/备注的源码范围，统一补全、搜索定位与引用绑定。
- 对局部源码改字和结构操作使用编辑范围与上次结构协同匹配，优先保留明确未删除节点的 id。
- 重复文本重排、整篇替换等无法无歧义匹配时，保留失效连接并显示“需重新选择”，不把连接挂到猜测出的节点。
- 含连接数据的文档从源码切到结构化编辑时，重新锚定连接到节点字段，源文本与数据在同一提交中转换；保留原有格式转换提示。
- 按只读标签页切换、浏览节点或打开详情不应重写 Markdown 原文。

### 6.2 两种 Markdown 导出

| 模式 | 目的 | 保留内容 |
| --- | --- | --- |
| 普通 Markdown（保留现有默认） | 阅读与外部编辑器互通 | 可读内容、普通链接文本；文末可读“关系”清单；明确提示稳定 id 等信息可能丢失 |
| 带 Bike 元数据的 Markdown（显式选择） | 在 Bike 间单文档往返 | 以上内容加受控 HTML 注释，保存文档/节点身份、引用绑定和关系 |

元数据协议建议：`<!-- bike:document:v1 <base64url-json> -->`，协议需在 M0 定稿。

必须满足：

- 不改变编辑中的原文缓存；只在导出边界生成，导入时识别移除，不在正文界面显示。
- 元数据只含当前文档，不含整个工作区、凭据、备份路径、索引或本机偏好。
- 带规范化正文摘要与节点映射；仅在校验匹配时按位置恢复身份。外部修改后按明确唯一映射恢复，无法确认的连接保留为待修复。
- 不能靠注释运行代码、读文件或发起请求；限制解码后大小（初始建议 2 MiB），严格校验字段、深度、目标与偏移。
- 非法、超限或未知版本元数据必须提示“可导入纯正文/取消”，保留原文件；不默默忽略损坏并声称无损。
- 网页和 MCP 的 Markdown 导出路径统一，不能继续让 `getDocumentMarkdown` 直接跳过元数据策略。
- 单独导入文档时，如果当前库已有同 id 文档，按副本导入并映射内部连接；完整工作区载入按现有“替换并先备份”流程保留 id。

### 6.3 其他输出边界

| 格式/通道 | 1.6.0 要求 |
| --- | --- |
| 工作区/文档 JSON、iCloud JSON | 完整保留知识字段、回收站与未知扩展，主恢复格式 |
| 文档级 Sync | 按原文档 revision 传输知识字段，不新增服务器全局关系表 |
| MCP JSON/compact | 返回有界的引用、入链、出链与关系，显式 `truncated` 与计数；只读解析不改工作区 |
| MCP Markdown | 支持相同纯正文/带元数据策略；既有工具参数兼容，新增参数可选 |
| HTML/PDF | 展示可读引用及关系清单，不承诺重新导入无损 |
| OPML/FreeMind | 延续树结构导入导出，导出有知识连接的文档时提示不能完整保留 |

MCP 写入工具暂不新增关系编辑；现有改名/改字/移动/删除必须维护或标明连接有效性，不能留下看似成功的旧偏移。MCP 与前端采用同一套解析/映射语义，通过跨运行时样例测试约束。

## 7. 搜索、全局标签与索引

### 7.1 索引结构

- 文档表：id、标题、更新时间。
- 节点表：`documentId + nodeId`、父链、路径、正文、备注、任务状态、原文定位信息。
- 标签索引：规范化标签 → 来源节点；保留展示拼写。
- 引用索引：来源定位 → 目标 id、状态；反向表由有效解析结果生成。
- 同文档关系索引：节点入边/出边、隐藏或失效边计数。

索引存于内存，可从正常文档重建；首次打开初始化，之后按变化文档更新。标签页刷新、导入/恢复、远端下载或 MCP 文件重新载入时使对应缓存失效。

名称变化会影响未绑定弱链接解析，因此文档标题索引变化后还需重算相关弱链接，而不只更新被改名的一篇。

### 7.2 检索语义

- 标题、正文、备注默认参与搜索；表格与代码内容可通过“包含代码/表格”选项显式加入。
- 支持中文子串与英文大小写不敏感匹配；不引入分词服务或嵌入模型。
- 标签沿用 Unicode 名称，比较采用 NFC 规范化和明确大小写规则；默认大小写不敏感，显示第一次记录的原文。
- 标签与链接解析都跳过代码语境、URL 片段和已转义文本，不把 `#标题` 或 URL anchor 错当标签。
- 多个标签按 AND 过滤；任务条件为全部、未完成任务、已完成任务，非任务主题不误匹配任务条件。
- 排序为标题精确命中、标题包含、主题命中、备注命中，再按文档更新时间；同分使用稳定 id 排序。
- 结果高亮用安全文本节点渲染，不能注入原始 HTML。

### 7.3 性能目标

验收基准建议：100 篇文档、合计 20,000 主题、200,000 字以上中英文内容；关系密集文档另含 300 个主题与 200 条边。

- 正常规模搜索输入约 150ms 防抖，首批结果目标 300ms 内可见。
- 10,000～20,000 主题不在每次按键时全量重复 flatten 与扫描。
- 初始索引重建目标 2 秒以内，期间可继续编辑并显示索引状态。
- 标签统计按节点去重，同时显示涉及文档数，重复同一标签不虚增主题数。
- 这些是待实测目标，不是已测结果；如主线程达不到目标，增加 Worker 或分块构建，并在验收记录说明测试机器和样本。

## 8. 单文档关系线

### 8.1 操作

1. 在主题菜单或详情栏选择“添加关系”。
2. 通过列表/搜索选择同文档目标主题，填写短标签，例如“依赖”“导致”“下一步”。
3. 创建后在详情栏查看出关系/入关系；可改标签、改目标、反转或删除，均可撤销。
4. 脑图提供“显示关系线”开关，单独绘制虚线箭头和标签；开关状态是本机视图偏好。

参考 `docs/login-flow-cross-relations-demo.svg` 的层级实线与关系虚线语义，不要求复制该示例的多列坐标布局。

### 8.2 规则

- 只连接持久节点 id，不允许以临时脑图根 id 作为端点。
- 禁止自己连自己；同一有向端点对只保留一条，反向边允许。
- 允许关系成环，因为它只是表达联系，不参与树形父子约束或流程执行。
- 折叠/聚焦导致一端不可见时不画该边，显示隐藏关系计数；不能把端点偷偷换成可见祖先。
- 端点已删除时显示失效关系清单，用户决定删除或重新连接；自动重命名不能修复身份缺失。
- 边与节点共用同一缩放/平移坐标；箭头、标签需与节点一同变化，不能遮住主要编辑点击区域。
- 本版提供自动曲线布局，不提供控制点拖动、自动排版优化或碰撞消除引擎。
- 单文档新建关系上限建议 1,000 条；超过上限的导入保留数据并提示，禁止静默截断。
- 同时绘制最多 200 条，超出时提供选中节点相关边/过滤提示；数据总数与显示数分别呈现。
- 标签建议限制 40 个 Unicode 字符，超出时提示而非直接截断。

关系线不会改变 Markdown 层级、节点父子关系、树排序或节点数量。

## 9. Electron 自动 iCloud 备份

### 9.1 启用方式与范围

- 新增桌面“备份设置”：自动备份开关、路径、最后本地写入时间、状态、立即备份、查看外部变更。
- 默认关闭，经用户首次启用后持久保存到当前 Electron 配置目录；不自动把已有用户切换为后台写文件。
- 初版沿用现有 iCloud 路径，不引入可变备份根目录；更多备份目标另行规划。
- Web 保留手动文件夹导出，不模拟不可见的后台目录授权。
- 文案区分“已保存到本机”“已写入 iCloud 文件夹”“iCloud 云端传输由系统处理”，不把文件写入成功当成远端上传成功。
- 自动备份仅包含工作区 JSON；1.5.0 独立 IndexedDB 版本历史仍不在其中。

### 9.2 调度规则

1. 只在 IndexedDB 已成功提交的内容版本上排队，localStorage 备用保存不作为自动备份权威源。
2. 内容最后一次成功保存后防抖 5 秒；持续编辑时最长约 60 秒排队一次最新已保存版本。
3. 只切换文档、搜索、收藏、最近打开或视图不触发新备份；内容、回收站、引用和关系变更可触发。
4. 单队列执行手动和自动任务，只保留最新待执行版本，不同时写多个全工作区文件。
5. 正在写 W1 时产生 W2：完成 W1 后继续处理 W2，W1 回调不得把 W2 标成已备份。
6. 退出时尽力处理已保存待备份任务，等待上限建议 3 秒；未完成时下次启动提示并重试，不阻塞退出或把未完成显示成功。

### 9.3 基线与外部写入

不能复用“读最新文件哈希后无条件更新 expectedRevision”的做法：

- 主进程管理队列、最后成功 revision、源保存版本 ticket 与备份内容摘要，前端展示状态；明确迁移旧前端保存的手动备份基线。
- 首次启用时文件不存在可创建；内容与本机已保存版本相同可建立基线；已有不同内容必须先比较/载入/下载备份，不能自动覆盖。
- 在现有文件锁内比较真实文件内容哈希与期望基线，再做原子写入。锁只用于当前设备的协作进程，不宣称可锁住其他设备的 iCloud 写入。
- 同一设备的自动/手动队列使用源保存 revision 和任务序号淘汰旧请求；多窗口共享同一主进程队列，拒绝较旧窗口的任务。
- MCP 或其他进程修改同一文件后，自动任务返回明确 `external-change` 并暂停；保留新文件，不重复重试覆盖。
- “查看外部变更”先比较与下载双方副本；用户选择载入文件后，经本地保存成功才能更新基线并恢复自动备份。
- 用户选择使用本机内容时，也必须先保留外部副本并在锁内重新验证已比较的哈希；外部又变化则重新提示。
- 主进程返回结构化错误码，如 `external-change`、`stale-source`、`unavailable`、`permission`、`write-failed`；不能靠中文错误字符串判断状态。

本版只改善文件数据新鲜度：只读 MCP 可在下一次读取拿到最近完成的备份。MCP 写入文件后桌面不会自动采纳，仍需用户检查并载入；完整双向数据桥留在 1.8.0。

### 9.4 失败与快照轮换

- 数据加载失败、跨页保存冲突、工作区恢复中、来源版本无法验证时暂停调度。
- 路径暂不可用、权限或磁盘错误不阻断编辑；提示一次并显示失败状态，提供重试/关闭。
- 短暂错误建议按 5/30/120 秒最多重试 3 次，之后暂停自动重试；外部修改冲突不使用这套重试。
- 自动备份内容与上次相同不重写，不反复产生时间戳文件。
- 现有时间戳副本保留上限 20 个。自动任务最多每 10 分钟生成一份轮换副本；手动备份及显式替换外部文件前另生成副本，同样受上限约束。
- “最后备份时间”只取实际成功的任务；旧任务失败/成功都不能覆盖较新任务状态。

## 10. 本机导航偏好

收藏、最近打开、保存筛选建议由独立 `navigationStore` 管理，数据量小、带版本并处理写入错误；不写到文档正文，不增加 `updatedAt`，不污染撤销和同步。

| 偏好 | 初始规则 |
| --- | --- |
| 收藏 | id 集合，最多 500 个正常文档；取消收藏立即生效 |
| 最近打开 | 最多 50 项，按实际打开时间去重；恢复最近使用的视图/目标作为本机偏好 |
| 保存筛选 | 最多 30 个命名筛选，允许重命名、覆盖、删除；引用失效时提示修复 |
| 文档移入回收站 | 导航中隐藏；恢复后可重新显示原收藏状态 |
| 彻底删除 | 清理已失效 id |
| 完整工作区替换 | 重置最近打开，按新工作区校验收藏与文档范围；不把旧 id 强套到无关数据 |

本版不宣称这些偏好参与备份或跨设备同步。若后续要同步收藏/文件夹，应另设导航元数据协议，不能依赖当前文档同步“顺带完成”。

## 14. 发布门禁、兼容与回退

开工和最终候选均以当前 CI 的 Node.js 22.13.0 为基线，Linux/macOS 执行依赖安装、全量测试、类型检查、构建与 MCP smoke；新增依赖须先核对最低 Node/Electron 要求。

发布前必须：

1. A01–A24 有测试或实际交互证据；无法覆盖的外部环境明确记录，不能以单元测试替代 DMG 操作。
2. 链接不因重名/Markdown/id 重建误接；重命名、关系编辑可以回退。
3. 外部文件变化和较旧备份请求均无法静默覆盖最新数据。
4. 1.5.0 的数据保护回归通过，未知字段在所有写入链路保留。
5. 最终候选提交的远端 CI 通过后再打标签和上传资产；实现阶段不提前承诺已发布。
6. 用户确认开发/发布后，才执行对应阶段。本次计划整理不包含这些操作。

回退约束：

- 新字段保持可选，避免纯读取就改变旧库。升级前导出 JSON；迁移失败保持只读或暂停保存。
- 1.5.0 的未知字段保留能力不等于语义兼容：旧版改 Markdown、复制或移动后可能留下失效知识连接。建议升级常用客户端，降级后避免编辑含连接的文档。
- 真正回退优先使用升级前 JSON，不能通过删除 `knowledge` 字段来声称无损。
- 版本历史恢复旧正文可能使入链/关系失效，应显示状态并允许修复，不能按同名对象自动重新挂接。
