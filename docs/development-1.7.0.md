# Bike 1.7.0 开发计划

整理日期 2026-11-09（Asia/Shanghai）

版本主题为附件与发布质量。产品定位沿用本地优先的个人知识工具，以 Electron macOS 桌面版为主。

本计划已完成 1.7.0 的本机实现与候选验证，分支为 `codex/development-1.7.0`。用户于 2026-11-09 确认继续使用 ad-hoc 签名发布，Developer ID、公证与原生自动更新的签名验收顺延。附件、ZIP、携图导出、清理及兼容路径的当前实现与证据见 [实施记录](implementation-1.7.0.md)。Intel/Universal 的交付继续取决于评估和对应实机验收。

## 1. 依据与开发基线

需求依据为 [路线图](roadmap.md) 中的 1.7.0。仓库已记录 `v1.6.1` 发布，发布提交为 `08c3bdec9a61810c0784ef2d666a9ed34499129c`，见 [发布验证](publish-verification-1.6.1.md)。开始开发时应从包含该发布提交的最新开发基线建立分支，并记录实际 commit。

## 2. 版本目标与范围

1. 用户把图片或文件加入主题后，应用重启和断网期间仍可使用。
2. 用户导出一个工作区 ZIP，在空白环境恢复后，文档、主题身份和附件内容一致。
3. Markdown、HTML、PDF 与脑图图片导出能够呈现真实图片，演示视图能够展示节点图片。
4. macOS 正式制品完成 Developer ID 签名、公证、stapling 和下载后首次启动验收。

完整使用路径为选中主题 → 粘贴图片或拖入文件 → 离线查看 → 删除附件引用 → 撤销恢复 → 导出 ZIP → 在干净环境导入 → 打开图片及文件。

## 3. M0 需要冻结的设计决策

以下为建议默认方案，进入对应实现前记录验证结果与最终选择。

| 决策 | 建议默认方案 | 冻结条件 |
| --- | --- | --- |
| 本地存储位置 | `<userData>/attachments/`，通过应用导入导出迁移 | 正式包内可读写、升级保留、空间不足可诊断 |
| 格式版本 | 纯文本工作区继续支持 v1，首次创建或接收附件引用时迁移到 v2，文档附件字段独立 version 1 | UI/MCP/备份均识别 v2，迁移前 v1 副本可取回，旧客户端安全拒绝 v2 |
| 附件标识 | 原始文件字节的 SHA-256，文件名和显示名独立保存 | 同内容不同名称去重，同名不同内容分离，校验规则跨运行时一致 |
| 图片类型 | PNG、JPEG、WebP 内联展示，其他格式作为文件附件处理 | 正式 Electron、PDF、SVG 与演示视图的解码路径验证通过 |
| 旧 `imageName` | 原值保留为旧图片引用，用户重新选择文件后绑定真实附件 | “本地图片占位”、相对路径、远程 URL 均有确定行为 |
| 清理策略 | 用户发起扫描和确认，候选进入隔离区，建议保留 30 天后复核清除 | 所有引用根可枚举，扫描不完整时停止删除 |
| 归档完整性 | ZIP 包含当前文档、回收站与这些内容引用的原始附件 | 清单、哈希与数量可核对，独立于原电脑成功恢复 |
| 正式分发 | 先完成 arm64 签名公证链路，分别评估 x64 与 Universal | 账号、证书、凭据和对应架构的运行环境到位 |

### 3.1 格式升级与回退

- 在首次升级前刷新输入草稿，保留可下载的 v1 工作区副本，记录原 revision 和迁移标识。准备失败时终止升级。
- v1 → v2 迁移保留文档 id、主题 id、引用、关系、回收站和 Markdown 源码。旧 `imageName` 无对应文件时继续作为旧引用显示。
- 文件导入、Sync 下载和历史恢复首次带入附件元数据时，同样先完成格式升级。即使本机尚未取得二进制，也按 v2 处理。声明为 v1 却携带新附件字段的输入须进入迁移或受保护路径。
- v2 的读写入口同时更新 UI、MCP、手动导入、恢复入口、自动备份与部署包。未知附件 schema 保留原始数据并进入受保护状态。
- 向旧版本导出单独提供 v1 兼容副本，列出真实附件的损失。用户也能恢复迁移前副本，恢复时说明它对应的时间点。
- Sync Server 的文档接口需要附件能力校验。携带附件的新文档应拒绝未声明支持能力的旧客户端覆盖写入，并返回可诊断的升级提示。工作区版本校验之外，单独验证这条路径。
- 与不支持能力校验的旧 Sync Server 连接时，附件文档的上传须受保护，保留本机内容并提示升级服务或使用 ZIP 迁移。

M0 交付兼容矩阵，覆盖旧 v1 文件、新 v2 文件、旧客户端、当前客户端、旧/新 Sync Server、MCP 与带元数据 Markdown。

### 3.2 建议数据结构

附件元数据随所属文档保存，节点持有引用，二进制按哈希保存在本地库。文档级数据能够随现有文档同步、快照与 JSON 导出传递。

```json
{
  "attachments": {
    "version": 1,
    "items": {
      "sha256:<64位小写十六进制摘要>": {
        "mediaType": "image/png",
        "byteLength": 123456,
        "width": 1600,
        "height": 900
      }
    }
  },
  "nodes": [
    {
      "id": "node_example",
      "attachmentRefs": [
        {
          "assetId": "sha256:<64位小写十六进制摘要>",
          "name": "路线截图.png",
          "alt": "路线说明"
        }
      ]
    }
  ]
}
```

示例只展示新增字段。实际文档和节点继续保留已有必需字段。文件名与替代文字属于引用，同一文件在不同主题下可以采用不同显示名。

原始字节、哈希、媒体类型和尺寸需要验证。缩略图为可重建缓存。可用、缺失、校验失败等状态由本机派生。文档内容签名覆盖元数据和引用，机器路径、缓存与读取状态保存在本机运行状态中。

## 4. 工作包拆解与验收

### A01 数据契约、迁移与统一操作

- 实现附件元数据和引用的校验、收集、复制、移除及损失报告，UI/MCP 复用共享规则，并补充 `.d.mts` 契约。
- 同步更新 `src/types.ts`、`src/migrations.ts`、`mcp/bike-core.mjs`、共享 Markdown 元数据与文档签名。
- 节点复制、跨文档移动、文档复制、回收站碰撞恢复时，携带对应附件元数据，复用原始 blob。
- 新增/替换/移除引用通过现有文档提交和历史模块完成。跨文档操作保持整体撤销语义，磁盘导入结果需绑定目标文档、主题和编辑基线。
- 新格式升级与旧文档编辑保持明确边界，避免只打开纯文本工作区就触发格式升级。

验收覆盖 v1 → v2 → 保存重启、JSON/元数据 Markdown 往返、节点移动与碰撞恢复、跨文档撤销，以及未知 schema 的原数据保护。

### A02 本地附件服务与读取边界

- 新增独立附件服务，建议放在 `electron/attachment-service.cjs`。原始对象按摘要分目录保存，提供有界导入、读取、校验、枚举及隔离操作。
- 主进程接收用户选择或拖入的文件，通过可信窗口 IPC 校验和短期导入凭据处理。读取接口接收 assetId，按库内规范路径定位。
- 采用临时文件 → 流式计量与哈希 → 校验 → 原子安装的写入流程。并发导入相同内容时验证并复用已存在对象。
- 正文引用只在附件落盘成功后提交。正文 CAS 失败、目标主题删除或用户取消时撤销未提交任务，留下的孤立对象交由清理流程处理。
- 为跨文件系统与 IndexedDB 的操作保存恢复记录。启动时区分已完成引用、未提交导入和损坏对象，支持重试及诊断。
- 使用受控协议或受限资源读取路径供界面加载，校验目录边界、符号链接、请求来源与实际文件类型，按选定机制收紧正式包 CSP。
- 缩略图按需生成和缓存，限制解码并发，文档切换、组件卸载和窗口关闭时释放资源。

验收覆盖同文件连续/并发导入、相同名称不同内容、中文和 Emoji 文件名、零字节文件、权限失败、空间不足、哈希冲突异常、崩溃重启及越界读取。

### A03 主题附件编辑与预览

- 文件选择、粘贴和拖入统一进入导入队列。默认附加到当前选中主题，未选中时要求用户选择目标，并显示批次进度和失败项。
- 区分主题拖拽与文件拖拽。粘贴图片与粘贴文字分别路由，中文输入法组合输入期间保持编辑行为。
- 大纲显示缩略图或文件条目，支持图片预览、文件另存、修改显示名/替代文字及移除引用。打开普通文件经显式用户操作调用系统程序。
- 脑图按缩略图尺寸和附件条目计算主题边界，保留折叠、关系线、缩放、聚焦及菜单操作。
- Markdown 源码采用稳定的附件 URI，预览经附件解析服务显示图片。四视图切换保持主题身份和引用，原有相对路径及远程 URL 继续区分显示。
- 批量导入支持取消。一批成功项作为一次可撤销提交，失败项显示逐项原因。
- 同步或导入后找不到文件时显示缺失状态，提供重新定位和通过 ZIP 补齐入口。

验收路径为三种导入方式 → 四视图切换 → 修改与移除 → 撤销重做 → 关窗重开 → 断网查看。另测导入过程中切换文档、删除目标、撤销、同步替换及退出。

### A04 引用生命周期与安全清理

附件保留集合应至少覆盖以下引用根。

| 引用根 | 保留条件 |
| --- | --- |
| 当前工作区正常文档 | 仍存在有效引用 |
| 回收站 | 条目尚未彻底删除或过期清理 |
| 本机持久版本历史 | 仍有保留快照引用该对象 |
| 撤销和重做栈 | 仍可恢复到包含该附件的状态 |
| 本机备用副本及替换前恢复副本 | 副本仍可供用户恢复 |
| 进行中的导入、导出、备份与恢复 | 任务持有附件租约 |

- 引用计数作为派生缓存，删除判定从引用根复核。读取历史/备用副本失败时标记扫描不完整并停止删除。
- 用户先查看可清理文件数、字节数、保护原因及缺失引用，再确认移动至隔离区。
- 扫描和清理间核对 revision、历史集合及任务租约变化。增加新引用或新任务后重新判断。
- 隔离期内撤销、历史恢复或导入重新引用同一对象时自动恢复。到期后再次确认不可达，才物理删除。
- 旧版本 MCP 外部文件写入、库读取失败和备份暂停期间采用保守保留策略。

验收覆盖删除主题后撤销、清空回收站后恢复旧快照、先扫描后新增引用、清理与导出并发、重启后隔离恢复，以及文件系统异常。任何仍可恢复的正文都应找得到对应原始附件。

### A05 工作区 ZIP 导入导出

建议包结构为 `manifest.json`、`workspace.json` 和 `attachments/<digest>`。清单独立记录归档版本、工作区格式版本、源 revision、文件数、字节数与每个对象的 SHA-256。

- 导出先刷新草稿并取得已保存工作区和附件租约，固定该次导出视图。流式生成归档，失败时保留可诊断结果。
- 导出前按配对导入预算预检工作区、条目和字节总量，保证本版生成的完整归档可以由本版恢复。超出支持范围时给出明确原因，M0 用大库样本确认限制是否适合日常备份。
- 当前完整归档范围为正常文档、回收站及其附件。本机版本历史、内存撤销栈、导航偏好和服务凭据在导出界面及清单中说明范围。
- 存在缺失或损坏附件时列出引用位置，阻止标记为完整归档。用户可显式选择导出正文和可用附件，包内记录不完整状态。
- 导入先在 staging 中检查路径、重复条目、清单、schema、数量、字节预算、哈希和引用闭合，再展示文档/附件摘要。
- 拒绝绝对路径、`..` 穿越、符号链接、特殊文件、越界解压、加密条目和无法安全识别的版本。超限、取消及损坏均在提交前终止。
- 工作区恢复沿用明确的替换流程。替换前为当前工作区和附件生成完整可恢复副本，保留 CAS，提交失败时可重试或回退。
- 提供“补齐附件”路径，只接收与现有引用摘要一致的对象，保留当前正文，适用于另一设备只同步到元数据的情况。

验收在独立应用数据目录执行。核对文档/主题 id、链接、关系、回收站、文件字节及附件显示。另测残缺包、改字节、重复名称、解压炸弹、并发编辑、空间不足及中途退出。

### A06 iCloud 备份、Sync 与 MCP

**自动备份**

- v1 工作区继续沿用现有 JSON 流程。v2 采用 JSON 加内容寻址附件目录与版本清单，保持 MCP 可读取的工作区文件入口。
- 对同一已保存 revision，先写齐并校验附件，再安装清单，最后提交 JSON/完成标记。恢复时只采用附件齐备且清单匹配的版本。
- 旧版本备份、待写队列和受保留的快照共同保护云端附件。清理云端对象单独核对保留集合。
- 延续外部修改暂停、来源凭据、窗口归属、A→B→A、关闭前刷新和失败可见性。MCP 外部写入 JSON 后，元数据与原清单的差异也需要检测。
- 状态分别呈现本地保存、备份目录完整写入和附件缺失。真实跨设备 iCloud 传输单独验收。

**Sync 与 Web 兼容**

- 文档元数据、引用和来源信息参与现有指纹、revision CAS、冲突与删除流程，保证纯附件变更也被识别。
- 为附件文档引入最小能力校验，并记录服务升级顺序，防止旧客户端写回时丢失引用。
- 下载元数据后保留缺失引用，文本仍可编辑，图片区域提示本机未取得文件。JSON 文档同步成功与附件可用性分别显示。
- Web 在缺少本地附件服务时提供缺失状态、元数据保留和受保护写入，部署包补齐格式校验所需共享模块。

**MCP**

- 精简读取返回附件 id、显示名、媒体类型、大小和可确定的本地可用状态。未知状态显式标记。
- 现有文本/节点写入保留附件引用，遵守 `dryRun`、`expectedRevision`、文件锁和写入预算。对附件库的可用性检查按配置和来源范围执行，库范围未知时反馈未知状态。
- MCP 导出带元数据 Markdown 时保留附件身份并报告二进制携带范围。文件路径读取和附件写入工具另行定义权限后扩展。

验收覆盖自动备份关闭/开启、外部 JSON 修改、缺附件备份恢复、两个设备元数据同步与 ZIP 补齐、旧客户端写入拒绝，以及 MCP 文本改写后 UI 重新载入。

### A07 Markdown、HTML、PDF 携图导出

| 格式 | 交付形态 | 保真边界 |
| --- | --- | --- |
| 工作区 JSON | 结构、附件元数据与稳定引用 | 明确提示二进制通过 ZIP 或附件库保存 |
| 带元数据 Markdown 包 | `.md`、相对路径附件及清单组成 ZIP | 保留 Bike 主题身份、知识数据与附件绑定 |
| 普通 Markdown 包 | 标准图片/文件链接与附件目录组成 ZIP | 给出稳定身份、关系等格式损失 |
| HTML 包 | HTML 与相对路径附件组成 ZIP | 离线阅读，保留现有表格、代码及关系说明 |
| PDF | 文件内嵌图片，普通文件显示名称与说明 | 阅读制品，附件原始文件通过归档获取 |
| OPML/FreeMind | 延续当前格式能力并更新损失报告 | 明确附件与知识元数据保留程度 |

- 提供异步附件 resolver，复用原有导出格式逻辑与损失报告。导出使用固定文档快照和任务租约。
- Markdown 原始源码缓存、图片链接与元数据同步维护，覆盖改名、节点移动、删除、撤销和再次导入。
- 同名附件生成确定且无冲突的相对路径，处理中文、Emoji、空格和特殊字符。HTML 的文件名与替代文字正确转义。
- PDF 按页内可用尺寸排版，处理横图、长图、透明图片、连续图片和跨页正文，必要时生成临时解码结果。
- 缺失、损坏和不支持预览的附件在导出前给出清单，避免静默省略。原始字节留在归档。

验收使用导出的实际文件，在断网环境解压阅读和重新导入。逐一核对图片字节、路径、主题身份、链接、关系、空表格、代码、替代文字与损失提示。

### A08 脑图 PNG/SVG 与演示图片

- 脑图导出复用界面布局和节点度量。默认导出当前聚焦、折叠和关系线开关所确定的全部可见内容，按内容边界计算画布。
- PNG 支持透明或当前主题背景，设置输出尺寸/像素预算。超限时提示调整尺寸或使用 SVG。
- SVG 内嵌图片数据并处理文字、关系线、箭头、颜色和中文字体回退，交付文件可独立离线打开。
- 图片加载失败、超长主题、密集关系线、浅色/暗色及边缘节点均有确定布局，导出前等待所需资源完成。
- 演示视图覆盖顶层主题本身的图片和子主题图片，按空间等比显示，保留备注、翻页、全屏与键盘行为。

验收检查 PNG/SVG 的完整边界、实际像素、图片、文字和关系线，并在应用外打开。演示验证横竖图、多图、缺图、全屏和持续翻页后的资源释放。

### A09 XMind 与幕布兼容评估

- 收集可合法纳入测试的脱敏样本，记录来源软件版本、导出格式和期望结构。
- 幕布样本覆盖多层级、备注、任务、链接、图片引用、中文和 Emoji，对 OPML/Markdown 执行实际导入比较。
- XMind 先识别拟支持的文件族、压缩包结构、主题模型、关系与附件。复用 ZIP 安全校验，限制解析预算。
- 输出样本支持矩阵、字段映射、损失提示、依赖许可与维护成本、预计工期及是否纳入本版的结论。
- 若纳入实现，增加对应工作包、资源预算与回归样本。保留原文件并报告不能表达的数据。

本包验收物为可复现样本和评估结论，实际导入能力按最终范围单独标注。

## 6. 资源预算与测量样本

下列为待 M0 验证的初始上限，所有入口采用一致口径并在触发时保留原始内容。JSON 继续遵循现有 64 MiB 等预算，附件二进制单独计量。

| 项目 | 建议初始预算 | 超限行为 |
| --- | --- | --- |
| 单个图片原始文件 | 32 MiB，解码尺寸不超过 4,000 万像素 | 可按普通文件导入，内联预览给出原因 |
| 普通文件附件 | 单文件 128 MiB | 拒绝该文件并保留其余批次结果 |
| 单次批量导入 | 100 个文件、合计 512 MiB | 分批处理，提交前显示总量 |
| ZIP 导入导出 | 压缩包 512 MiB、解压累计 1 GiB、最多 10,000 条目 | 导出预检，解压时持续计量，触发后清理 staging |
| 图片解码与缩略图 | 同时最多 2 个任务，缩略图最长边 512 px | 排队、取消、可重建缓存 |
| PNG 输出 | 最多 3,200 万像素 | 提示缩小尺寸或选择 SVG |

媒体类型检测、原始字节和解码像素分别校验。扩展名或声明 MIME 通过后，继续执行解码和预算检查。

固定样本包含 100 文档/20,000 主题、单文档 20,000 主题/200 次独立编辑，以及 100 张图片、200 次重复引用、50 个普通文件、超大图片和损坏文件。记录导入总耗时、首屏可交互时间、搜索 p95、切换视图耗时、GC 后 heap/RSS、磁盘占用及缓存释放。

沿用 1.6.1 的测量机器和条件建立本次基线。纯文本场景 p95 或 GC 后内存退化超过 20% 时进入门禁复核，M0 冻结绝对值及测量波动范围。图片任务结束、取消和反复切文档后，内存与缓存应回到预算内。

## 7. 验收矩阵

| 场景 | 必须观察的结果 |
| --- | --- |
| 断网与重启 | 已导入图片/文件可用，缺失附件状态准确 |
| 批量导入部分失败 | 成功与失败逐项可知，成功项可整体撤销，原正文保留 |
| FS 成功、正文 CAS 失败 | 引用未误提交，孤立对象可回收，重试不会重复占空间 |
| 导入、保存或恢复中崩溃 | 重启后可诊断及恢复，工作区不引用未完成写入 |
| 删除、撤销、回收站和历史恢复 | 对应原始附件仍可访问 |
| 清理与新引用并发 | 活跃引用和任务租约保护附件 |
| ZIP 空白环境恢复 | 文档、主题、链接、关系、回收站及附件哈希一致 |
| 恶意或损坏 ZIP | 拒绝处理，现有工作区与库仍可正常使用 |
| Markdown/HTML/PDF/脑图导出 | 离线打开，图片完整可读，布局和损失报告准确 |
| Sync 元数据到第二设备 | 正文可用、缺失附件可辨识、ZIP 补齐后恢复显示 |
| 旧客户端与旧服务 | 不支持的写入被保护，新字段和二进制仍保留 |
| MCP 外部写入与自动备份 | 引用保真，外部修改触发保护，完整备份状态准确 |
| 浅/暗、窗口与输入法 | 四视图可操作，预览和菜单可达，原生组合输入有效 |
| 正式下载与升级 | 签名、公证、stapling、首次启动与原数据保留通过 |

真实剪贴板、文件拖拽、中文输入法、第二台设备 iCloud 和对应架构实机分别取证。未具备的环境记录为待验证，并据发布门禁决定候选状态。
